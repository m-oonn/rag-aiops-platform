# 候选身份延续实现与离线验收（2026-10-22）

本次在现有自主调查链路中实现候选 ID 引用、创建步骤与证据历史延续，以及引用校验。基于 main 的 830a0da 后续工作树变更，不改调查图、实验组配置或工具权限；不宣称真实模型已能稳定遵守 ID 协议。

## 1. 实际流程与入口

replanner 委托 InvestigationStrategy → 结构化决策 → _resolve_candidate_identity 解析引用、保留已有必要预期 → _validate_alternatives 校验排除依据 → 更新候选和现场观测 → 原有保护/改向调度 → 检查与结论门槛 → state、checkpoint 和诊断结果。

源码：[investigation.py](../src/agent/aiops/strategies/investigation.py)。新增字段是 Alternative.hypothesis_id 与 InvestigationDecision.hypothesis_id，默认空字符串；当前候选 ID 同时写入调查记忆和 diagnosis.hypothesis_id。既有 API/SSE 传递完整 diagnosis 字典，请求字段不变；前端本次未修改。

身份解析和必要预期恢复在排除校验之前完成，避免模型改写 expected 后，程序按新预期错误地验证“已排除”。模型原始建议仍保存在 model_suggestion，能区分模型提出的值与程序接受的值。

## 2. 候选 ID 协议

| 输入 | 工程行为 |
| --- | --- |
| 已知候选填写已保存的 hypothesis_id，解释文字改变 | 沿用该候选；不重建 ID、birth_step、seen_observations 或支持/反证计数 |
| 新候选 ID 留空 | 服务器根据规范化解释与结构化预期生成 ID；同文字但不同预期可形成独立候选，同一次决策也可区分 |
| 旧输出没有 ID，解释精确匹配已保存候选 | 条件一致或缺失且匹配唯一时，沿用旧 ID；不重新计算旧检查点的 ID |
| 旧输出没有 ID，描述匹配多个已有候选且无法由条件区分 | 停止本轮后续检查，说明需要明确 ID，不猜测选择 |
| ID 不在本次调查的已保存候选中，或显式引用缺少解释 | 停止后续检查，不将它变成新候选 |
| 显式引用的对象、操作或字段与已保存预期不一致 | 拒绝本轮候选更新，保存原候选和预期；真正的新方向应留空 ID 并作为新候选提出 |

字段默认值兼容旧结构化输出和旧 proposal。ID 引用来自本次 state 的候选集合；未知引用不能引入其他调查的状态。

不填 ID 后将解释改为不同措辞，仍可能形成新候选；系统没有自动识别所有同义解释。没有保存结构化预期的自由文本候选，程序也不能仅凭 ID 证明它的含义完全一致。以上是当前边界，不通过额外模型或 embedding 掩盖。

## 3. 必要预期、证据与错误处理

已有结构化预期绑定在候选上。显式沿用 ID 时，删除预期或改变 expected 都不能抹掉旧预期；程序恢复旧值并记录校验说明。对象/操作/字段改变则拒绝引用。要表达新预期，应作为新候选提出。

继续先检查旧领先候选的旧预期是否遇到可靠新反证。ID 和文字变化不会消除反证；两项机制开关只控制原有保护与调度，身份、观测更新和结论门槛在四组中共用。

candidate.evidence_ids 表示当前条件对应的证据；新增 evidence_history 累积曾关联的证据 ID，旧检查点从已有 evidence_ids 补齐。旧观测指纹和计数延续，相同结果换一次采样或回读不会重复计数。

历史关联不等于当前有效引用。证据是否可支持结论仍由既有目标、时效、范围和原文校验决定，不能从 evidence_history 绕过这些门槛。

引用错误记录在 hypothesis_tracking.identity_issues 与 validation_issues，并作为停止原因传递。整份候选提案先验证再写入，避免前半部分已经更新、后半部分才发现非法引用；已通过现场校验的观测仍更新已有候选的关系和历史。错误提案不能确认根因或健康；独立现场事实成立时，仍可诚实报告故障层。

测试入口：[test_investigation_mechanisms.py](../tests/test_investigation_mechanisms.py)、[test_probe_investigation_flow.py](../tests/test_probe_investigation_flow.py)。新增 27 个用例，另调整已有图恢复测试，对程序分配的 ID 和恢复后的 ID 明确断言。

## 5. 下一步与带读入口

下一项只处理“模型无充分排除依据却放弃核查的候选，如何获得有限检查机会”。继续复用统一的排除校验，明确保护调度与普通调查的差别，并用四组固定输入验证；本次没有实现该扩展。

本次带读围绕一个候选：查看首次分配的 ID 与 birth_step → 用该 ID 改写解释 → 核对 ID、年龄和观测计数 → 再看反证是否改变实际下一检查。你的关键掌握点是：文字可以变化，已知候选的身份与历史延续；保留身份不表示忽略反证。本次测试通过不代表用户已独立掌握这些代码。

## 1. 引言

**目的**：定义问题、点明隐藏故障诊断难点、给出贡献清单。

- 1.1 研究背景：AIOps 故障诊断现状，LLM Agent 诊断的兴起与局限
- 1.2 问题定义：**隐藏故障**（症状复杂而根因简单）的两类典型错误——过早放弃简单假设 / 被复杂症状带偏（素材：设计文档 §1.1）
- 1.3 研究内容与贡献：
  - C1 机制：旁开式动态分类（假设保护 + 矛盾触发 + 孵化/复活 + 证据收敛）
  - C2 诚实性：证据充分性门控 + 报告双轨（人读/机读），信息缺失不虚报
  - C3 可解释性：信念轨迹/证据映射/决策记录结构化输出，A 组 4/4 结构非对称 + ECE 0.1645 + 稳定性 100%
  - C4 鲁棒性：MCP 按 server 容错 + 本地日志降级源 + topic 对齐，F 组停 monitor 8/8、停 cls 7/8（残差为诚实 uncertain）
- 1.4 论文组织结构

**写作要点**：贡献 C3/C4 用数字立论（ECE 0.1645、8/8、40/40），避免空泛。

## 3. 方法：旁开式动态分类故障诊断机制

**目的**：全文核心，机制的形式化描述。素材：设计文档 + 方法-证据裁判规则 + 架构文档 §2/§3。

- 3.1 总体框架：Plan-Execute-Replan 状态机 + 策略注入（架构文档 §5.1 决策判定顺序 8 分支）
- 3.2 假设空间与信念更新：log-odds 公式、support/contradict 系数（1.5/2.5）、保护期、证据批量归一（架构 §4.2/§4.3）
- 3.3 两级证据裁判：LLM 语义裁判（primary）+ 规则关键词回退，严重级加权 ERROR/WARN/INFO = 1.0/0.9/0.45，混沌注入锁定（方法文档）
- 3.4 决策与旁开机制：矛盾触发旁开、概率跃迁（≥0.20）、隐藏假设孵化、深度回溯重解释复活（设计文档 §2/§3）
- 3.5 诚实性设计：`_evidence_sufficiency_problem` 证据充分性门控，四类结论语义（正常/推测/未定根因/证据不足）；`diagnostic_meta` 结构化字段五态（工作报告 §4 方案 B + 报告双轨）
- 3.6 可解释性输出：belief_history / evidence_log / top3 置信集 / 决策记录（架构附录·可解释性实验结果 A 组）

**写作要点**：每条机制配「触发条件 + 动作 + 期望行为」三要素，与 §5 实验一一对应。

## 5. 实验设计与结果

**目的**：论文证据主体。素材：实验报告 + 工作报告 §3 指标 + 盲测设计 spec。

- 5.1 实验设置：场景集（8 端到端 + 40 盲测 + 扰动集）、基线（T2 默认线性策略）、指标（命中率/Δ/步数/ECE）、固定种子确定性路径
- 5.2 机制验证（核心实验）：非预埋盲测，动态 vs 基线，Δ = 机制净贡献；**Δ≈显著正值 → 机制有效**（素材：blind-eval spec §7/§13，结论 40/40）
- 5.3 可解释性三组：
  - A 决策可审计性：4/4 维度 T2 结构性缺失（非对称即结论）
  - B 置信度校准：47 点 ECE 0.1645，系统性低估、无过度自信、置信与正确率单调正相关
  - C 结果稳定性：固定种子 3 次 8/8 一致率 100%
- 5.4 鲁棒性四组：
  - D 输入扰动（同义改写）8/8
  - E 模型降级（规则 vs LLM 语义）15/15 逐场景一致
  - F 工具故障：MCP 单点（停 monitor 8/8）+ 日志证据缺失（停 cls，修复前 5/8 含 3 虚报 → 修复后 7/8，残差为诚实 uncertain）
  - G 复杂度梯度（0→2 难度干扰+否定+级联）15/15/15，步数仅 4.0→4.33
- 5.5 诚实性案例研究：F 组修复前后对比（虚报确定 vs 证据驱动结论），`conclusion_state` 区分 conclusive/insufficient
- 5.6 实验小结与威胁有效性

**写作要点**：5.2 是机制贡献的判定性实验，务必给出 Δ 与逐场景明细；5.4 F 组配「修复前后」对照表体现诚实性收益。

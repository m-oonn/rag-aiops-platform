# 四类检查状态的正式输出与浏览器验收

2026-10-27，在 main 当前工作树完成。验收范围是摘要覆盖状态从实际执行器、调查策略、图、SSE到重开SQLite刷新和前端显示的一致性，不是自主效果实验。

## 发现和修复

旧版进程返回缺少 skipped_count、memory_unavailable_count 或 cpu_unavailable_count 时，摘要原来默认显示0，并且不标记部分结果；这会将未知覆盖写成已经完整检查。新增两条反例先复现失败，再修正 investigation.py：缺失计数显示 unknown，进程覆盖计数缺失标为 partial。端口和进程同时区分 returned（实际返回条数）与 matched（匹配总数），不再把匹配总数当作已展示条数。修改只影响摘要及调查记忆，不改变结论门槛、工具权限或机制开关。

## 正式链路

新增 tests/test_probe_summary_output_flow.py，复用现有历史输出测试的ASGI和任务清理模式；运行库、checkpoint和原文使用本轮独立目录。六条工具返回全部为构造数据，与collector字段形状一致：

| 返回 | 摘要状态 | 验证边界 |
| --- | --- | --- |
| 进程应用的Windows服务查询 | not_applicable | 不是服务停止 |
| 未配置事件通道 | not_applicable | 不是零事件或业务健康 |
| 端口查询AccessDenied | unavailable | 不是零监听 |
| 资源快照含不可读磁盘 | partial | 只能使用已经返回的数据 |
| 进程快照缺覆盖统计 | partial | 缺失不是0 |
| TCP失败且HTTP子检查不可用 | observed | 已取得TCP失败事实，不补写原因 |

仅替换模型决策和工具返回；API、执行器、证据入账、调查策略、持久化图、SSE与刷新读取均为项目实现。核对证据ID、操作、采集时间、事件先后、状态及报告；只有TCP失败进入故障发现，结果为故障层定位，未确认深层原因。关闭服务对象并重开SQLite后，调查摘要与报告相同；审计员原文与构造输入逐项相同，普通用户无原文权限。

旧checkpoint兼容另行构造：从本轮checkpoint去掉摘要status，再经正式刷新接口读取，报告不变且没有自动补造状态。操作不涉及历史源文件，也没有新增模型或工具执行。

## 浏览器验收

开始时5273和8200没有监听，未启动任何服务。用本轮独立Vite构建，在本人新建的内存Chrome中拦截全部请求并返回静态资源和上述正式输出；页面URL为127.0.0.1:5273，但不存在对应服务启动。假token仅绕过本地页面导航，不作为真实认证验收。

检查开始诊断按钮消费SSE、最终四类提示、刷新后调查卡片文本一致、六条摘要引用的键盘/鼠标定位、焦点及目标完整进入视口。普通用户没有原文按钮，错误中的img字符串为纯文本。再加载正式接口生成的无status旧checkpoint输出，确认旧错误提示兼容。

成功轮九个API请求（一个POST、八个GET）全在浏览器内返回，转发后端为0；未知请求及页面脚本错误均为0。三张截图保存并视觉检查 states-refresh.png，未见乱码或HTML执行。本轮没有验证真实流式网络延迟或服务断线。

最初两轮因回放脚本漏处理站点图标vite.svg，严格请求检查失败；页面错误数组为空。补齐图标处理后复验通过，失败记录 browser-output.txt、browser-second.txt 保留，不记为成功。最初两条回归失败保留 red.txt/red.xml。

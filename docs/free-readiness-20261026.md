## 本轮实现

复用 `verify_windows_local_faults.verify(..., evaluation_preflight=True)` 的真实专用业务、Probe/MCP、日志和 reset，不新建第二套故障控制器。`verify_boundary_rounds` 保留独立正常业务两轮验收的旧调用方式，完整控制器使用正常、下游不可达、应用错误各四轮，最后正常恢复，共13轮。四轮是连续重置覆盖，不代表执行了正式 G00/G10/G01/G11 自主实验。

每轮在重置前获取旧观测、记录带时区边界、拒绝旧返回和重新读取的旧日志，再调用既有 reset。reset 返回独立核验的 HTTP/进程/监听快照；入口、下游的真实 Probe 返回必须与快照的状态和正文一致。新日志必须来自当前监听进程，且有支持本场入口状态的日志行。进程归属使用实际监听 PID，兼容 Windows Python 启动器及子进程。控制器快照仅用于验收，不作为 Agent 现场证据或答案。

失败保留轮次、场景、原文、工具轨迹和错误类型；若下一轮在取得旧观测时失败，不覆盖上一轮已通过的状态。已有逐进程清理逻辑继续处理所有本轮进程，不将未知监听宣称为已释放。未降低生产证据、结论或费用门槛。

## 免费复现入口

在项目根目录，用已有venv：

```powershell
& ./.venv/Scripts/python.exe scripts/verify_windows_local_faults.py --evaluation-preflight
& ./.venv/Scripts/python.exe -m pytest -q
```

第一个命令会创建独立runtime目录，在独立端口启动专用业务/Probe/MCP，真实制造应用级故障，完成后清理本轮进程，保留报告和失败；不要加`--run-model`。第二个命令默认排除integration，包含专用业务进程单测。前端在frontend目录执行`npm.cmd test`；需要构建时指定新的独立outDir，不覆写旧验收产物。

核心流程可从 `scripts/verify_probe_observation_boundary.py` 的 `verify_boundary_rounds` 带读：旧返回被拒绝 → reset返回独立事实 → 新工具结果比对 → 当前日志PID与内容比对 → 保存本轮状态。系统验收通过与用户能够独立解释、操作分别记录。

**场景本身能够区分两个故障层。** 模型实际从仍在监听的localapp与下游连接/监听/进程缺失取得区别，并未只凭503猜测。当前没有证据支持继续增加场景复杂度或扩大场数。

**停止审计出现可定位的不一致。** 第8步记录与审计使用前轮候选重建的结果均为`no_eligible_saved_candidate`，均没有检查、最终plan为空；但两项候选的拒绝理由分别是“重复查询、raw_hash未变化”和“已有结果，复核需目的与原证据”。现有严格对照将此记为失败。已保存[离线重建](../runtime/competing-live-20261104-a/blocked-review-reproduction.json)，没有修改审计器或改判原场。还需要核对当轮检查参数/重复复核字段与审计所用前轮状态的具体差异，不能仅凭双方都停止便宣布审计误报。

# 故障控制器知识条件留痕与变化阻断

日期：2026-10-23。本轮为免费实现与离线验证，未启动付费模型或完整故障控制器。

## 实际缺口与改动

规划前 local_runbook_retrieval 原有文件哈希，但控制器没有在每场开始前比对；隔离 MCP 的索引片段及配置也没有统一记录。因此服务地址相同不代表知识条件相同。

新增 scripts/knowledge_conditions.py，面向控制器自有 Markdown/BM25 夹具记录相对文件名与 SHA-256、完整索引片段、库14、重排关闭和最低分配置、相关源码指纹、rank-bm25/fastmcp 版本。清单自身使用确定性 JSON 指纹，不含绝对语料目录、故障答案或凭据。索引构造由 verify_windows_probe_graph.create_local_knowledge_server 与清单共用 fixture_chunks，避免两套片段定义漂移。

verify_windows_local_faults 在复制隔离 runbooks 后写 knowledge-manifest.json；免费预检和模型子进程均传递清单。控制器启动调查前核对本地基线，每次使用独立 sample_id 保存核对记录；子进程在模型预算和客户端初始化前核对，结束后再次核对。控制器要求返回结束阶段的通过记录、相同指纹和入口地址，才继续处理该场结果。知识关闭对照不要求与开启组相同；四组主实验仍禁止知识关闭。既有无清单入口保留兼容，不把历史结果补标为已验证。

新增 --knowledge-manifest 仅在显式配置隔离 runbooks 和知识 MCP 时可用。失败保存 knowledge-conditions-*.json 并抛错；前后哈希一致不表示期间每个瞬间都未变化。该记录为本地构造条件核验，remote_index_verified 始终为 false：没有声称完整远程索引或主 PDF 库15已通过版本核验。

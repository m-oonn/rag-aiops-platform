# 身份提议拒绝后继续已保存的合法检查

2026-10-30。**已修复：本轮模型候选身份错误不再自动中断此前保存的合法检查。** 错误提议仍整轮拒绝，不自动改 ID，不采纳该轮新检查，不重置候选年龄；本轮没有付费调用。

## 修复位置与流程

`src/agent/aiops/strategies/investigation.py` 新增 `saved_candidate_followup`，接在既有现场独立补查之后。仅当整轮候选身份提议已被拒绝、且现场策略没有选出检查时，重新读取上一份已保存候选：

1. 业务必须已经解析，目标与当前 Probe 一致。
2. 只考虑此前 active 或仍在期限内的 protected 关键候选。dropped、excluded、unavailable、非关键和保护已到期的候选不借此恢复。
3. 当前可靠观测不能反驳该候选的有限预期；原有条件、范围、工具、参数、查询进度与重复守卫全部重新校验。
4. 检查必须具有完整具体参数，且全部是已开放 Probe 查询。没有参数的旧检查和非 Probe 工具不通过此恢复路径。
5. 仅将原来保存的整项检查排入计划；已经执行、已经取得同查询结果、失败、不可用或取消的原样检查不能再次排入。无合法下一步时如实停止，不称检查穷尽。

已有的现场策略仍优先：如果已经观测到白名单 loopback 下游 TCP 失败，可先检查监听及映射进程/日志；如果还没有该事实，则可以继续先前已保存的进程、依赖等检查，而不猜测下游故障。

身份、条件、出生步、原提议和主候选保持原样；真实新观测仍能更新候选的观测关系。继续检查由 `identity_recovery` 记录来源候选 ID、出生步及精确检查。只有最终确实排入计划才记录恢复。

`scripts/mechanism_behavior.py` 从**前一轮**候选和本轮现场证据、此前失败记录重建检查选择，再核对实际计划、全部工具参数与成功执行。新增 `saved_check_continued` 表示已保存检查的延续；不计入保护/矛盾改向成绩。四组使用同一规则，原两机制开关不变。

保存的检查可能包含多个工具，因此不套用旧 `policy_selected_check` 的单工具参数格式；执行器原有 `next_arguments` 逐工具守卫继续生效。开发中的执行器测试先发现该格式冲突，已修调度元数据；未放宽执行器参数校验或修改其实现。

## 1.1 研究背景

随着微服务与云原生架构的普及，线上系统的调用链深度、组件数量与部署频率持续上升，故障的**表现形式**与**真实成因**之间的距离被不断拉大。一旦服务发生异常，排障人员往往要在监控指标、应用日志、链路追踪等多类数据源之间反复切换，才能逐步逼近根因。

长期以来，这类工作依赖 OnCall 值班工程师的人工经验，其固有缺陷已被业界反复讨论，可归纳为三点：**响应慢**——人工逐项排查耗时，故障影响范围随时间持续扩大；**质量不稳定**——夜间值班、新人值班时的排障质量显著下降；**经验难沉淀**——资深工程师的排障思路停留在个人经验中，难以复用与传承。

大语言模型（Large Language Model, LLM）在推理与工具调用（Function Calling）能力上的突破，使"Agent 化诊断"成为一条新路径：由 LLM 自主规划排查步骤、调用监控与日志工具采集证据、再依据观测结果迭代收敛，即 **Plan-Execute-Replan** 范式。相较于固定阈值的异常检测与传统规则脚本，Agent 诊断的价值在于能够处理"未曾预设的故障组合"，并以自然语言给出可读的诊断说明。

然而，将 LLM Agent 直接用于生产故障诊断仍存在三方面局限：

1. **结论不可审计**：输出通常只是一个根因字符串，无法回答"凭什么这样判定"，工程师难以据此复核与追责；
2. **置信度不可靠**：模型在证据不足时同样给出语气确定的结论，形成"**虚报确定**"——结论看似可信，实则来自先验猜测而非证据支撑；
3. **工程链路脆弱**：诊断高度依赖外部工具服务（监控、日志），任一单点不可用即可能导致整条诊断链路失效。

本文关注的，正是上述局限之下被忽视的一类诊断场景——**隐藏故障**。

## 1.2 问题定义：隐藏故障与两类典型错误

**定义 1.1（隐藏故障）** 指**症状复杂而根因简单**的故障：系统表面呈现出大量、跨组件、看似指向复杂成因的异常信号（级联报错、多服务 5xx、超时与重试日志），但真实根因往往只是一个单点问题，例如 CPU 饱和、内存溢出（OOM）、连接池耗尽或网络抖动。

这类故障对 LLM 诊断构成特殊挑战：其难点不在模型的推理能力上限，而在于**证据在时间上的到达顺序与强度分布**会系统性地误导假设管理。具体表现为两类典型错误：

**E1 · 过早放弃简单假设（premature abandonment）**
面对复杂症状，诊断主体容易采纳"复杂症状 ⇒ 复杂根因"的先验，将一个起初正确、但证据尚未充分积累的简单假设（如"CPU 饱和"）过早降权或淘汰，转而追逐更"戏剧化"的成因。其后果是诊断方向被自身先验带偏，而正确假设再无机会被重新检验。

**E2 · 被复杂症状带偏（symptom hijacking）**
大量级联 ERROR 日志主导了证据权重，把诊断引向调用链**末端**的次级故障（如消息队列积压、线程池耗尽），而链路**首端**的真实根因（如缓存不可达）因日志数量稀少而被淹没。其后果是"定位到了现象，而非成因"。

两类错误的共同特征是：**错误并非源于模型能力不足，而是源于假设管理机制的缺失**——现有 Plan-Execute-Replan 流程只提供"线性推进"，既没有对早期假设的保护机制，也没有在证据矛盾时"旁开"出新分支、并在后续证据支持下恢复既有假设的能力。这正是本文要解决的核心问题。

## 1.3 研究内容与贡献

针对上述问题，本文设计并实现了一套 **AIOps 故障诊断系统**，其核心是一套**旁开式动态分类诊断机制**。系统采用 LangGraph 编排的 Plan-Execute-Replan 状态机，通过 MCP（Model Context Protocol）接入监控、日志与运维知识库三类工具服务，并在关键结论处引入人工审核。本文的主要贡献如下：

**C1 · 诊断机制：旁开式动态分类**
提出以**假设空间**为核心的动态分类机制，将诊断过程形式化为可审计的信念更新过程：

- **信念更新**：以 log-odds 形式更新假设概率，支持证据系数 1.5、矛盾证据系数 2.5，后验概率钳制于 [0.01, 0.99]，使矛盾证据具备更强鉴别力；
- **假设保护**：新建假设享有 2 轮保护期，直接针对 E1，避免简单假设因证据积累不足而被过早淘汰；
- **矛盾触发旁开**：当领先假设被矛盾证据否定且诊断步数尚少（< 5）时，不线性推进而是旁开出新的排查分支，直接针对 E2；
- **孵化与复活**：对长期低概率的隐藏假设，在满足步数与概率条件（top 概率 ≤ 0.35）时主动孵化验证步骤；对已被淘汰的假设，在净支持度达到门槛（支持与矛盾命中数之差 ≥ 2）时执行**深度回溯重解释**，将其复活并置顶验证步骤；
- **证据收敛**：以高置信门槛（0.70）与次选排除（最小差距 0.20、次选概率低于 0.30）共同判定诊断收敛。

同时设计了**两级证据裁判**（LLM 语义裁判为主、规则关键词裁判为确定性回退），并按日志严重级对证据加权（ERROR / WARN / INFO = 1.0 / 0.9 / 0.45），抑制噪声日志对信念更新的干扰。

**C2 · 诚实性：证据不足不虚报**
提出**证据充分性门控**机制：当关键证据源缺失时，系统不输出貌似确定的结论，而是显式声明"证据不足"并给出并列候选。报告采用**双轨输出**——人读部分以"结论 / 结论（证据不足）"区分语义，机读部分以结构化字段 `diagnostic_meta` 输出证据充分性、结论状态、首选假设及其概率，使程序可消费、可断言。
该设计在工具故障实验中获得了直接收益：日志服务停服时，修复前命中 5/8 且其中 3 例属于"虚报确定"（把先验猜测输出为确定结论）；引入门控与降级证据源后提升至 **7/8**，且残差 1 例为显式的"证据不足"，不再虚报。

**C3 · 可解释性：结构化信念轨迹**
系统输出信念轨迹、证据—假设映射、Top-3 置信集与决策记录四类可解释性材料。实测结果表明：与仅输出结论的基线相比，该机制在 **4/4** 个可解释性维度上呈现结构性差异；在 47 个采样点上，**近似期望校准误差（ECE）为 0.1645**，呈**系统性保守低估、无过度自信**（47 点中 45 点的实际正确率不低于其置信度），置信度与正确率单调正相关；固定随机种子重复 3 次，8 个端到端场景结论一致率为 **100%**，诊断结果具备可预期性。

**C4 · 鲁棒性：工具降级下的可用与可信**
针对诊断链路对工具服务的单点依赖，实现了三项加固：**MCP 按 server 逐个加载**（单点失败仅丢失该 server 的工具，而非整体丢弃）、**本地日志降级源**（日志服务不可达时回退读取本地副本，并标注降级来源）、**topic 对齐**（修正降级路径中的主题漂移，避免读错服务的日志）。
实测结果：停用监控服务后命中率 **8/8**，停用日志服务后 **7/8**；输入同义改写扰动 **8/8** 结论一致，规则裁判与 LLM 语义裁判**逐场景 15/15 一致**；在干扰、否定与级联的复杂度梯度下 **15/15/15** 全命中，平均诊断步数仅由 4.0 增至 4.33，说明机制在难度上升时以极小的步数代价维持了准确率。

此外，为支撑上述实验的**可复现性**，本文构建了确定性测试底座：以固定种子的 LLM 桩（llm_stub）替代真实模型、以剧本化场景覆盖 8 个端到端用例、并以非预埋的盲测生成器批量构造 40 个场景，盲测命中 **40/40**。需说明的是，该盲测场景的特征词仍来自同一词表，因此 40/40 应理解为"**在预设特征词表覆盖范围内**判定鲁棒"，而非对任意日志措辞的外推结论。

**贡献范围声明**：本文的实验结论建立在确定性桩与剧本化故障注入之上，验证的是"**给定正确计划与忠实工具结果时，证据裁判与动态决策机制的有效性**"；真实 LLM 的计划生成与摘要环节、真实分布式调用链的故障传播、以及超参敏感性，均不在本文验证范围内，相关边界在第 6 章逐条讨论。

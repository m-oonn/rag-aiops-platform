## 三、六维评审

### 3.1 选题价值 —— 优

**结论：选题合理、前沿，且问题定义质量高于本科均值。**

- **场景真实**：AIOps 排障的"响应慢 / 质量不稳定 / 经验难沉淀"痛点成立，与业界 LLM Agent 落地方向一致（`毕设选题说明.md` §2）。
- **问题定义可证伪**（关键加分项）：`引言.md` §1.2 把问题收敛为**隐藏故障**（症状复杂而根因简单）与两类典型错误——**E1 过早放弃简单假设**、**E2 被复杂症状带偏**。这不是"做一个系统"，而是"验证一个机制能否解决一个可观测的失效模式"，具备研究型毕设的必要形态。
- **与现有工作的差异点清晰**：可解释 + 诚实 + 鲁棒，区别于黑盒 LLM 报告。

**扣分项**：选题书承诺的技术蓝图（多智能体协同 + 知识图谱）与实际交付存在实质偏差，见 §3.6.1。

### 3.2 研究深度与创新性 —— 良（机制深，验证浅）

**结论：机制设计的深度与形式化程度达到硕士前期水平；但实证链条的"可复核性"不足，削弱了创新性的可信度。**

**深度充分之处**（均经源码核对）：

1. **假设空间 + 信念更新形式化**（`core/hypothesis.py`）：
   - log-odds 增量更新（support ×1.5 / contradict ×2.5），后验钳制 [0.01, 0.99]；
   - **批次原子更新**——把同批证据的 log-odds 先累加再一次性换算，从数学上消除"批次顺序偏置"（原始实现逐条更新导致先处理者先饱和，是真实修复过的缺陷，注释可查）；
   - 同源同步去重（按 `(source, step, target, relation)` 取最大强度）、多候选 logit softmax 竞争归一、新假设 2 轮保护期防误杀。
2. **两级证据裁判**（`core/evidence_judge.py`，492 行）：LLM 语义裁判优先，失败/禁用自动降级规则关键词；按日志严重级加权（ERROR/WARN/INFO = 1.0/0.9/0.45）。
3. **8 条决策规则的显式优先级**（`strategies/dynamic_classification.py` L473-634），顺序经代码逐行核对，与 `architecture.md` 附录完全一致（无常量漂移）。
4. **诚实性设计**：证据充分性门控 + 报告双轨（人读 `⚠️` 标注 / 机读 `diagnostic_meta` JSON 五态），把"不确定性"做成可程序消费的一等公民——这在同类工作中确属少见。

**创新性评价**：

- 旁开式动态分类（矛盾触发旁开 + 隐藏假设孵化 + 深度回溯复活）+ 诚实性门控，构成**机制层面**的实质创新，非工程堆砌。
- **但**：全部量化证据（ECE 0.1645、盲测 40/40、停 monitor 8/8、停 cls 7/8）**在本仓库内无法独立复核**——原始实验报告文件不存在（见 §3.5/§3.6.2）。创新性的可信度依赖作者自述，构成答辩风险。
- 作者已主动限定贡献边界（引言 §1.3 末"贡献范围声明"：仅验证"给定正确计划与忠实工具结果时，裁判与决策机制的有效性"），**这一学术诚实性是重要加分**。

**风险**：选题书要求"多智能体协同 + 知识图谱"，交付物是"单 Agent + 动态分类机制"。论文主题已在 `论文章节提纲.md` 中改写为"旁开式动态分类"，说明作者已意识到转型，**但选题书未同步修订、无变更说明文档**。若答辩追问"你承诺的知识图谱在哪"，将非常被动。

#### 3.6.3 【中】核心模块单元测试失效

`tests/test_dynamic_classification.py` **7/7 全部失败**，根因是**使用已被重构废弃的旧 API**：

```python
Hypothesis(label="基础设施/资源瓶颈", probability=0.85)   # 现模型要求 id + name
strategy.hypotheses = [...]                              # 现行由 HypothesisManager 持有
strategy.step_history = [...]                            # 该属性已不存在
```

该文件停留在 2026-06-25 的初版假设空间 API（提交 `3787248`），此后经历了大重构（`_MAX_STEPS` 8→12、7 条假设空间、复活的加入等）**但测试从未同步更新**。**恰好是毕设创新点所在模块**，这会被评审视为"创新机制缺乏单元级验证"。

**缓解路径**：按现行 API 重写该文件，或补一组面向 `HypothesisManager` 的信念更新测试（批次顺序无关性、保护期、softmax 归一），把"机制正确性"落到可执行断言上。

#### 3.6.4 【中】测试套件不可 CI 化

**缓解路径**：为外部依赖建 fixture/mock（或标记 `@pytest.mark.integration` 分离），补一个跑单测的 CI workflow。

#### 3.6.5 【中】工程对第三方免费额度强依赖

主推理模型随免费额度轮换（`glm-5.3` → `qwen3.7-flash-2026-07-15` → `deepseek-v4.1-flash`），`settings.py` 留有长达 20 行的额度探测史注释。项目完成度存档 §3.1 记录了因 403 额度耗尽导致**实验中途降级、污染观测**的事故。

**缓解路径**：论文中固定实验所用模型与版本，并在实验设置章节明确"模型可替换性"讨论；若可能，用付费稳定模型复跑一次关键实验。

#### 3.6.6 【中】验证范围局限（作者已自述，需在论文中显性化）

全部证据基于 `llm_stub` 确定性桩 + 剧本化 mock（单服务简化拓扑）：

**这是优点也是风险**：作者已在 `修复工作总结报告.md` 第 6 章逐条诚实声明（10 条，五维展开），**学术诚实性远超本科均值**；但论文正文若未把这章写好，评审只会看到"命中率 100%"的虚高陈述。

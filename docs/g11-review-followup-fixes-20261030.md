人工判断不是自动验证正确性，也不自动生成 `smoke_passed=true`、四组实验放行或新付费授权。此前 assessment 和 source-audit 中的 pending 是生成时快照，保留原样；当前人审状态以审核表和本次回执为准。

## 修复后的实际流程

1. 调查策略先验证主检查的工具、参数、区分问题及是否已经执行。当主项不可执行时，复用当前模型提议中的关键未决候选，寻找合法且尚待完成的区分检查；经既有身份、业务范围、反证及失败守卫后再转查。不凭空编造新候选，不绕过两机制开关。
2. 若仍须停止，在记忆状态和最终报告中一致写明：本项检查受阻，系统没有独立验证其余检查是否穷尽。该修复不能保证发现模型未提出的全部有效检查。
3. 进程查询上下文明确“先枚举并按配置身份匹配，再截断返回列表”。报告及结构化结果新增带证据编号的独立采集说明，列出枚举、匹配、跳过、返回和截断情况；不由未发现进程推断启动或退出历史。模型原有解释保留，说明其覆盖解释未独立核验。
4. `diagnosis_result` 将已解析业务配置和有效观测传给建议生成器。同一显式配置服务、同一动作的依赖/端口/进程建议归并，保留关联对象、故障标签和全部引用。仅凭名称相似不合并；远程依赖、缺映射或同端口多服务存在歧义时保留独立建议。前提、风险及处理后验证继续保留。

实现入口：[调查策略](../src/agent/aiops/strategies/investigation.py)、[人工建议](../src/agent/aiops/recommendations.py)。调用链仍为调查策略裁决 → diagnosis_result → 报告及状态保存，未更换图或新增依赖。

# 运维 Agent 测试反馈循环

## 一句话

每轮都追踪同一条链：**故障场景 → 可用证据 → 模型理解 → 合法检查计划 → 工具实际执行 → 新证据被消费 → 有引用的解释和报告 → 人工确认**。找出最早断开的环节，只修这个断点；先用保存输入离线回归，再决定是否需要真实模型验证。

## 每轮怎么做

1. **确认场景能测目标。** 写清预设故障位置、预期能区分的解释、现场可提供的证据和答案隔离方式。场景没制造出差异时，修测试环境；不要把环境问题算模型失败。
2. **看证据是否到达。** 核对采集源、权限、白名单、时间窗、结果和来源ID。证据没采到或没进模型请求，先修工具、网关或上下文接线。
3. **逐轮对照意图和执行。** 对每个模型提议核对结构化字段、业务守卫、最终计划和真实工具调用。提议缺字段时修输出契约或解析反馈；守卫拒绝合理检查时才查守卫本身。不能替模型猜参数，也不能削弱安全守卫。
4. **确认结果被用来更新判断。** 看新证据是否出现在下一轮请求，模型是否据此保留、排除或修正候选，并提出有鉴别力的新检查。没有证据支持的自然语言因果解释仍是待验证假设。
5. **核对结束质量。** 分开记录流程完成、故障层定位、机械审核、人工语义审核。报告要把来源事实和引用、支持的解释、处理及验证方法、未知与停止理由说清。机械通过不等于诊断充分，控制器恢复不等于人工处理成功。
6. **最小修复、离线回归。** 用失败场景的保存请求/轨迹复现断点；修复只覆盖该处及必要调用方，验证修前会失败、修后按契约工作、旧记录仍可读。保留原失败，不回写历史成绩。
7. **判断是否需要真实复测。** 离线能验证契约就先完成离线验证。任何新的真实模型调用须有明确的单场和累计边界授权；新失败、未知用量或不可比立即停止，不因剩余额度自动补跑。
8. **记录本轮并进入下一轮。** 保存输入、模型解析提议、守卫决定、实际工具、证据消费、报告、人审状态、成本和清理结果。下一轮从未解决且最靠前的断点开始，不跳到调提示词、换模型或加服务。

引用补齐边界核查结果：未发现新的错误收束。健康结论的自动引用只从当前范围内完整、最新且匹配的Probe观察构造；旧成功被更新失败覆盖时不能判健康。没有可识别现场发现、证据过期、目标不符、范围外或采集不完整时，故障回退不会制造定位结果。模型给出“管理员停止服务”等因果文字但漏掉引用时，程序报告仍只使用可独立识别的现场故障层，不采纳该因果文字。以上新增/加严回归均通过。

当前仍未验证的是**真实模型在纠正请求后是否会补齐合法 edge 日志检查，并继续消费结果收敛解释**。不再有可通过离线推断替代的工作；若要验证真实模型，需要重新单独获得单场与累计边界授权。人工三维审核仍pending，持续目标保持active。

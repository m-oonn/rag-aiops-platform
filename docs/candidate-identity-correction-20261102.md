# 候选身份纠正第一步（2026-11-02）

## 结果

已实现一次候选身份纠正，解决模型复用旧 ID 表示新对象/字段时直接结束调查的问题。身份校验保留；程序不自动把错误 ID 清空，不把新解释覆盖到旧候选。

## 处理流程

1. 正式策略仍先通过 `decide_from_evidence` 检查原提议，合法保存检查优先继续，不增加模型请求。
2. 身份冲突且没有合法检查可继续时，把冲突位置、旧条件、新条件和被拒原提议反馈给模型，仅允许一次纠正请求。沿用旧 ID 必须保持原条件，新候选可留空 ID。
3. 纠正结果针对原状态重新裁决，证据重新校验，范围、引用、精确参数、重复检查、机制及结论门槛不放宽。再次冲突不发第三次纠正请求，并在报告中说明。
4. 纠正过程失败时保存原拒绝提议、错误状态和证据；永久程序异常继续抛出。模型请求仍走已有入口与预算 transport，未添加绕过计费的客户端。一次纠正指一次额外结构化决策调用；原结构化格式降级与底层重试设置保持现状，实际 HTTP 请求均由预算器记录。
5. `investigation_memory.identity_correction` 保存原错误提议、冲突、次数和状态。行为快照/审计校验这些记录；纠正不计假设保护或矛盾改向收益。四组使用相同实现。

## 修改范围

- `src/agent/aiops/strategies/investigation.py`：正式异步策略、冲突反馈、一次纠正与失败留痕；只读 `decide_from_evidence` 保持不发模型请求。
- `scripts/mechanism_behavior.py`：纠正信息快照和审计。
- `tests/test_identity_followup.py`：四组纠正成功/再次失败、网络/预算/格式失败、优先执行保存检查、JSON 恢复后执行器直接执行、伪造纠正记录拒绝。
- `tests/test_knowledge_conditions.py`：补齐既有替代审计结果的症状输入 hash，生产 hash 门槛不改。

## 验证与限制

新增最小反例先复现 2 failed / 1 passed，失败原因是原实现只调用一次且没有纠正机会。修后定向及边界测试通过。默认后端全量首次为 1627 passed / 1 failed / 99 deselected；唯一失败是既有知识条件夹具缺症状 hash。补齐夹具并增加执行器恢复验证后，最终默认全量 **1629 passed / 99 deselected**，仅既存 PyMilvus 弃用警告；前后成绩不相加。

本步无新真实模型请求、无故障注入、无常驻服务重载、无前端变更、无提交推送。旧账本和历史运行产物不回填。测试使用替代模型与构造证据，不能证明真实模型稳定纠正或诊断效果提升。

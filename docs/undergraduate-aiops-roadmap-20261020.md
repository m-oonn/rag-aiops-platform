## 4. 阶段 A：先能讲清一次诊断

第 1 天入口：[从页面找到真正执行的诊断策略](undergraduate-day01-diagnosis-call-chain-20261020.md)。2026-10-22 用户已能复述请求、规划、工具、证据与再决策的主流程，并要求转入开发；分支细节曾需提示，尚不据此标记为可独立追踪全部代码。阶段 A 的历史运行带读与完整掌握仍待后续实践核验。

### 目的与实施

掌握一条调用链，而非通读全仓库：页面 → HTTP 接口 → AIOpsService → planner → executor/工具 → replanner → 证据校验与报告 → SSE/页面。

AI 的工作：核实实际入口和路由；整理 8—10 个关键函数的职责；选一份脱敏历史运行解释节点状态；记录相关源码差异、依赖、配置是否存在，不输出凭据。先相关测试，再按跨模块范围建立离线基线，保存失败与原因。

你的工作：每天读少量相邻代码，画数据怎样流转；亲自运行一个已有离线测试；解释一次工具返回与模型总结的区别。暂不从整段大型策略文件开始。

学习只覆盖眼前需要的知识：`async def/await` 是等待 I/O 时让出执行，不等于函数自动并发；HTTP 请求/响应是前后端交换数据；SSE 是逐条发送进度；TypedDict/状态是节点共享数据；reducer 决定追加还是覆盖。

### 验收与产物

你不用 AI 直接代答，能在代码里指出真实策略入口，画出一次检查怎样产生证据并影响报告，解释为何当前机制会被绕过。产物：一张当前调用图、一页术语与函数对照、一份版本和基线记录。

## 5. 阶段 B：让两个创新点实际改变调查

2026-10-22 首轮接入见[自主调查机制实现记录](aiops-investigation-mechanisms-20261022.md)：已接入有限防遗漏保护、条件反证改向与独立开关，离线测试验证实际图调度；尚未完成真实模型/故障验证、候选语义改写识别和完整实验验收，不标记阶段 B 完成。

### 5.1 先给机制一个可执行定义

假设保护：在有限且事先确定的保护条件内，暂缓因证据不足或尚待核实的间接反证而永久淘汰候选。保护期间仍更新信念、记录反证、允许核查；保护不意味着确认候选，也不意味着无限保留。当前实现按矛盾证据消耗 protection_rounds，命名与实际消耗口径需核实；论文必须写实际实现的定义，不能把证据条数写成调查轮数。

矛盾触发：对本次观察前的领先假设，新出现且目标、时间、范围匹配的有效证据与其预期冲突时，产生明确改向事件并优先选择有鉴别力的下一项检查。不能只改变一个状态标签；必须能解释为何后续检查因此变化。关闭时取消这条显式强制调度规则，但保留普通模型调查、证据更新和安全门槛。

两个机制都不负责直接判定最终根因。信念值作为内部排序分数；未经校准不把 0.9 宣传为 90% 的真实正确概率。

### 5.2 最小接入顺序

1. 追踪已有 HypothesisManager 和 EvidenceJudge 的输入输出、领域假设及适用范围，确认可复用部分。不要把旧 Linux/K8s 词表直接当成 Windows 业务事实。
2. 在现有自主调查路径维护稳定 hypothesis ID、预期现象、待查项、状态与证据关联；已有状态字段能表达就复用。
3. 只从通过来源/目标/时效校验的现场证据形成 support/contradict/neutral。模型负责语义建议，引用和字段校验继续确定性执行；自由文本因果仍需人工实验审核。
4. 更新信念并执行保护。记录候选为什么保留、什么时候退出保护；同一观测回读不能反复增加权重，截断或无权限不能变成对象不存在的反证。
5. 保存更新前领先候选，检测可靠矛盾，选择可执行的鉴别检查。检查仍受工具目录和参数守卫约束，不能让机制扩大权限。
6. 保留现有调查结果分级与证据门槛作为结束裁决。不能只把自主调查委托删掉，再让旧动态策略凭高分结束。
7. 把假设与配置保存在运行 state/checkpoint，隔离不同运行；按重复证据、错误引用、目标混淆、保护到期和矛盾误触发补最小反例。
8. 对每组相同输入验证只改变指定机制。旧复活、孵化等额外行为若影响结果，四组一律固定为同一设置；本轮不将它们再作为创新。

拟定接入边界：replanner 仍委托一个现场调查决策路径；该路径复用小型假设管理与证据关系逻辑，生成下一检查建议；现有证据裁决负责最终等级。开发时根据调用与测试确定最小改动，不另写第二个 Agent 框架。

### 5.3 四组定义

| 组别 | 假设保护 | 矛盾触发 | 保持一致 |
| --- | --- | --- | --- |
| G00 | 关闭 | 关闭 | 模型、工具和权限、知识、候选生成、证据更新、结论门槛、其他机制 |
| G10 | 开启 | 关闭 | 同上 |
| G01 | 关闭 | 开启 | 同上 |
| G11 | 开启 | 开启 | 同上 |

G00 仍是正常调查系统，可以通过模型判断改向；它不是故意制造的弱系统。四组是机制消融对照，不等于与所有主流 Agent 的综合比较。配置在运行开始固定、写入结果，优先每运行绑定，避免运行中修改全局 settings 导致串组；沿用现有配置结构，不预先造新配置平台。

### 学习与验收

你用 2—3 个候选和几条证据手动走状态表，再对照代码结果；能解释信念下降但候选暂未淘汰、普通更新与显式改向的区别。AI 完成接线和回归，你亲自切换配置、预测一次输出并解释差异。

验收：通过真实入口运行时确实经过机制；有证据 ID、前后候选状态、触发理由、下一检查和结果；四组可独立配置、恢复不串组。固定输入测试证明接线，真实模型少量复验才检验自主行为，两者分别记录。

## 6. 阶段 C：测试业务和故障要能检验机制

### 业务与基础场景

复用现有本机 HTTP 应用与下游，不新建商城或微服务平台。用户看到健康检查或简单业务请求；控制器改变本轮创建的进程、配置或受控错误模式，日志与探测反映真实状态。控制器与 Agent 分离，Agent 不能读取答案或控制文件。

先验收正常、下游不可达、应用自身错误三类；再按进度补应用退出、端口冲突、关键证据不可用。仅关闭本轮创建且核实 PID 的进程，不停止已有真实服务，不制造整机资源耗尽。

### 必须补的两类机制场景

**保护适用场景**：早期只能看到通用失败或局部正常，尚不能排除某个合理候选；后续专用日志/更具体探测才给出鉴别证据。候选保留可能使系统继续核查它。不能伪造故障事实、故意把答案藏在模型注释里，也不能保证一定先淘汰再靠保护救回；不发生早期淘汰本身也是实验结果。

**矛盾适用场景**：相似症状允许模型先形成一个合理候选；对该候选的针对性现场检查返回相反事实，例如被怀疑的下游检查正常，后续证据支持应用自身错误。不能强制写死初始错误假设来冒充自主诊断。若模型第一次就选对，记录未触发，不算触发成功。

先做固定证据序列测试，精确核验机制规则；再做真实业务和模型自主调查，核验外部行为。为证明后续证据的作用，优先采用工具自然获得的不同粒度信息；如使用预定阶段的证据可用性，须四组一致、与运行步数无关，并在实验方法披露。不同组不能因第几步才拿到真相而遭遇不同故障。

### 验收与产物

故障前、故障中、恢复后证据可独立核对；每场有答案、症状、允许对象、原始脱敏证据、恢复结果；运行 ID 随机，工具面不包含控制器。开发场景与最终保留变体分开。你能亲手制造并恢复一个故障，解释它与另一个同症状故障如何区分。

## 7. 阶段 D：RAG 和页面支持主线

### PDF/RAG

选 2—3 份允许使用、版本明确的小型排查 PDF，使用隔离知识库和独立数据输出，不覆盖现有索引。若现有架构无法隔离先补隔离方案，再入库。覆盖文本页、相似问题、无答案查询；扫描页仅在既有解析支持和任务需要时加入。

追踪 PDF → 页码/文档 ID → chunk → 索引 → kb 过滤 → 检索 → MCP 返回 → Agent 参考。抽查约 8—12 个查询即可作为小型功能验收，记录查询、正确段落与实际命中；不能据此宣称通用检索准确率。

验收：引用回到实际原文，错知识库不可混入；无答案不编造；手册只提供检查方法，不能改变现场 evidence 等级。四组固定文档和检索配置，实际检索路径可因检查变化而不同并记录。在线 embedding/重排有费用时纳入另外确认的额度。

### 页面

复用 Vue AIOps 页面，最小展示：当前检查、候选及状态、保护/改向事件、对应证据、下一步理由、最终结论和限制。优先列表或时间线，不为复杂动画做大改。学习用的机制开关可先在测试配置中，答辩页面不必给普通用户展示实验术语。

数据来自实际运行，不能用前端生成动画冒充决策。沿用证据访问权限与脱敏；API 契约新增字段需默认可选并兼容历史运行。浏览器检查真实登录、SSE、证据引用和重载后的结果。

## 8. 阶段 E：四组实验的具体流程

### 8.1 固定协议后再运行

每场保存代码与配置指纹、模型具体名称/版本信息、机制开关、知识语料版本、场景变体、随机顺序和开始结束时间。四组使用同样提示词结构，不给某组额外正确提示；必要机制状态由相同结构表达。模型非确定性必须承认，不宣称 temperature=0 就完全可重复。

先让 G11 在少量真实场景形成可用闭环；再做两个开发场景 × 四组各一次，共 8 场试跑，检查串组、事件缺失、泄题和费用。单独确认这轮额度后才运行。它是预实验，不与保留样本混成最终效果。

正式规模按费用测量决定：例如 4 个已固定的场景/变体 × 4 组 × 3 次，合计 48 场，是候选方案而非承诺。应同时覆盖机制适用和不适用/正常对照；如预算只能支持 16 场，就完整报告 16 场与限制，不能用重复改名凑独立样本数。

### 8.2 每次运行顺序

控制器重置业务与日志 → 独立确认故障事实 → 随机安排组别 → 给中性症状与允许对象 → Agent 自主检查 → 保存实际输入和轨迹 → 结束后揭晓答案 → 机械检查 → 人工审核 → 恢复环境。

每场独立 thread 和模型上下文，不继承前组聊天、调查状态或答案；公共检索缓存可保持同策略，答案/轨迹不得被后组检索到。重试与超时保留在记录中，未知费用如实标记，不重置累计账本。

### 8.3 指标及分母

| 指标 | 计算与判定 | 限制 |
| --- | --- | --- |
| 故障定位 | 结论对象和故障层是否与预设实际状态相符，n/N | 未完成计入 N 并单列；诚实未定位不算定位成功 |
| 健康与缺证据处理 | 正常是否误报，缺证据是否虚构确定原因 | 分场景报告，避免合并掩盖错误 |
| 保护作用 | 适用事件中候选是否被保留、之后是否实际核查、最终证据是否支持 | 保留候选不等于提高定位；保护错误方向的代价也记 |
| 矛盾改向 | 观察前领先候选遇到有效反证后，下一检查是否用于区分其他解释 | 无此触发机会的运行单列；不从分母静默删去 |
| 证据支持 | 关键结论能否由本场原文支持；机械与人工分别记 | 字符匹配不能替代因果审核 |
| 成本 | 工具数、模型请求、usage、耗时、费用/预留口径 | 预算预留与供应商实际结算分开 |

人工审核尽量先隐藏组别，只看预设事实、最终结论和证据；再看机制过程做行为审核。若只有你一人审核，报告单评审者限制；不把 AI 评分当作独立真实答案。

图表先展示逐场 n/N、失败和工具次数；样本少时不强求显著性。不承诺两个机制必然提升准确率。可能结论包括减少过早淘汰但增加检查、对某些反证有效、普通模型已会改向所以增益小；这些都是能讨论的本科实验结果。

### 完成标准

四组配置可核验；原始运行全部保留；至少能给出一个可追溯行为案例和一个失败/无增益案例；论文表格可从记录重新生成，旧 stub 的结果不混成真实模型实验。

## 9. 阶段 F/G：论文、演示和你自己的掌握

论文按学校格式调整，建议内容顺序：问题与目标 → 必要原理 → 两项机制的设计与定义 → 系统及真实调查链路 → 四组实验与案例 → 局限。不要把所有工程功能都列为创新。Pi 放相关工作或工程设计依据，避免声称发明其事件循环。

每完成一个阶段保存一张图、一段“为什么这样实现”、一个可追溯例子。机制参数必须对应当前代码；旧文稿中诸如固定计划、置信值、ReAct 能力的概括要核对文献与实际实现，不能照抄旧结论。

2 月形成完整草稿，不要求届时润色完美；3 月按导师意见修正论证和数据口径；4 月整理运行步骤、答辩讲述和复现；5 月按正式日期演示，至少提前两周固定演示版本。

演示建议约 8—10 分钟：介绍测试业务和症状 → 发起真实调查 → 展示实际产生的机制事件与证据 → 给出结论/建议 → 用实验记录解释四组差异。一次演示未必同时触发两个机制，不得补造事件；准备两个已验证场景和完整历史轨迹。

云端模型需要网络，预先检查连接。保留带时间、版本和场景标识的演示录像及脱敏历史结果作为故障预案；使用时明确是录制/回放，不冒充现场生成。

你最终需要亲自完成：定位真实执行的策略；解释一次 await 和状态更新；解释一条支持/反证；预测机制开关影响；运行一个相关测试；说明未定位与定位到故障层的区别；按实验表讨论失败，不背诵固定成功结论。

## 11. 每天一小时怎样用

常规分配：10 分钟回顾并预测今天结果；20 分钟带读一个函数或一小段调用；20 分钟亲手运行、切换或修改；10 分钟复述和记录。实验与写作日调整比例，仍只保留一个主任务。

AI 每次交付：本次改什么及原因、相关调用者、实际测试结果、3 个需要你回答的问题、下一次从哪里继续。你每次留下：今天读懂什么、亲手验证什么、哪里还不懂。答不出时先缩小概念，AI 不继续用更多抽象盖过去。

每周安排参考：2 天核心代码、2 天实践与回归、1 天实验/数据、1 天论文素材、1 天复述与缓冲。AI 编码与工具执行会占用实际会话时间，不能默认无限额外工时。

## 12. 控制范围与阶段失败处理

某阶段失败就缩小下一步，不堆新功能：机制接入失败先保留单个真实场景；真实模型费用超预期先减重复次数并诚实报告；RAG 某类 PDF 不支持就标明格式限制；实验没有提升就分析适用条件与代价，不换测试集直到结果好看。

现有 Termcp 与审批能力保留兼容，普通断线查看与已有 checkpoint 做必要核验；通用崩溃恢复、审批平台升级、跨主机 TLS 部署不作为本次本科主线必达项。异常时明确显示失败/可重试，不能假装恢复成功。

每阶段都保存代码、实验与论文素材的对应关系；不自动提交推送，不覆盖用户修改或历史运行，不把凭据写入文档。项目最终声称的能力只覆盖实际验证的业务、故障、工具和时间范围。

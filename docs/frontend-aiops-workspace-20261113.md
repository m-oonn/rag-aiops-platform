# AIOps 工作空间接口迁移与布局构建

日期：2026-11-13。

`docs/prototypes/aiops-v1/` 的页面结构已迁入正式 Vue 前端。登录及根路由默认进入 `/aiops`，保留原有业务路由。本次沿用现有后端接口，没有新增后端业务接口、修改数据库或调用付费模型。

## 页面与布局

- 主导航：故障诊断、最近诊断、运维知识库、平台维护；管理员账号管理沿用现有权限。
- 故障诊断：现象输入、终端高级选项、运行状态，以及结论报告／排查过程／候选原因／证据台账四个页签。运行时默认展示过程，完成后默认展示报告；页签支持键盘左右、Home、End 操作。
- 右侧展示本次诊断、最后记录的排查方向与证据来源。1100px 及以下改为单列主区域，767px 及以下信息卡也单列；手机导航使用抽屉，证据详情适应视口。
- 引用可定位证据记录；普通用户只读元数据，有权限的账号显式点击后读取脱敏现场证据。权限刷新撤回时清除原文缓存，并拒绝晚到响应。
- 平台维护复用现有文档任务、存储和 Worker 队列组件，旧问答、助手、通用智能体、评测及工作台入口仍可访问。平台依赖状态与被诊断业务健康分别展示。

## 接口对应

接口集中在 `frontend/src/api/aiops.js`，继续复用已有鉴权、错误处理和 SSE 客户端。下表统一省略 `/api/v1` 前缀。

| 页面行为 | 现有接口 | 使用边界 |
| --- | --- | --- |
| 启动诊断 | `POST /aiops` | 发送 query、session_id、terminal_enabled，接收 SSE |
| 恢复／刷新报告 | `GET /aiops/runs/{id}` | 使用服务端报告、状态、diagnosis、investigation |
| 按需读取步骤快照 | `GET /aiops/runs/{id}/steps` | 空结果提示未记录，可能未启用；不补造历史步骤 |
| 读取证据台账 | `GET /aiops/runs/{id}/evidence` | 元数据及服务端 can_read_raw 权限 |
| 读取单条证据 | `GET /aiops/runs/{id}/evidence/{evidence_id}` | 仅有权限且用户点击时发起，所有权和原文权限由后端核验 |
| 继续终端审批场次 | `POST /aiops/runs/{id}/continue` | 仅终端待审批状态，非通用重试／复核按钮 |
| 已登记目标状态 | `GET /aiops/targets/{id}/status` | 只查询已配置目标，不表示具备全局拓扑或目标 CRUD |
| 平台依赖 | `GET /health/dependencies` | 仅表示平台依赖的可用性 |
| Worker 与队列 | `GET /health/queues` | 复用既有 QueueMonitor 的展示与刷新 |

## 状态、历史与兼容

`/aiops?run={id}` 可恢复已有诊断；最近诊断页支持 ID 筛选和按 ID 读取。新建诊断清空当前选择并规范 URL，完成后刷新恢复新场次，避免旧 URL 参数覆盖新诊断。

现有后端没有诊断列表接口，最近诊断因此是本机最多 50 条的索引，按 JWT sub 隔离，仅保存 ID、状态、结论等级及本机更新时间，不保存查询、报告和现场证据。切换设备不会同步；每次读取报告仍由服务端检查所有权。旧版无账号的 last/pending 指针只在服务端确认所属账号后迁入当前账号，并移除旧指针。

断流操作显示为“断开进度连接”，不声称取消服务端运行。后端在早期事件中不一定返回诊断 ID；无 ID 时明确提示无法核实后续状态。普通 pending_review 不显示终端继续按钮。失败、待审批、等待复核及原因确认等级分别显示，流程完成不等同于根因确认。候选权重明确标注为模型权重，未经概率校准。

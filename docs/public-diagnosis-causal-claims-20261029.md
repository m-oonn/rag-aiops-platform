# 未核实因果解释的公开输出边界（2026-10-29）

## 本次问题

G11 完整场语义审读发现，模型提出的因果解释虽然在结构化裁决中被降为 `unresolved`，但原解释仍可能从故障报告、`diagnosis.alternatives`、未决问题、机制候选和 SSE 调查摘要进入用户界面。这样会让“待核实假设”看起来像系统已经确认或排除的原因。

## 处理方式

- `causal_claim_unverified` 的替代解释在公共诊断中统一显示为“该因果解释尚无可验证的现场条件”，并补充当前限制。
- 未决问题改为询问是否存在独立现场证据，避免把模型原句继续当作问题标题。
- 机制候选、下一检查、停止说明和 SSE 调查摘要沿用同一边界，避免通过候选追踪重新泄漏原文。
- 完整模型提议仍保存在 `investigation_memory.model_suggestion` 和内部 `hypothesis_tracking`，用于审计、机制行为分析与人工复核；不把内部提议直接作为用户事实。
- 只有条件谓词经过独立验证时，才保留原有的现场条件解释；本修复没有放宽根因、故障层或建议的证据门槛。

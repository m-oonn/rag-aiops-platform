# 针对性故障场景已设置并通过免费预检

当前可以用一套固定拓扑，检验诊断能否从同一个503症状区分两个故障位置。拓扑是 `edge → localapp → downstream`；三个角色均为独立临时进程，复用已有本地业务服务器，不增加常驻服务、公开API或依赖。

| 控制器注入的真实故障 | 入口症状 | 应用进程与监听 | 下游进程、监听与连接 |
|---|---|---|---|
| 停止localapp | 503 / temporarily unavailable | 不存在、无监听 | 存在、有监听、TCP正常 |
| 停止downstream | 相同503和响应正文 | 存在、有监听 | 不存在、无监听、TCP失败 |

这两个故障的直接原因是控制器停止对应的专用进程。验收只要求找到这个可观测故障位置，不能要求Agent在没有审计来源时查明历史操作者，或将缺少进程自行解释为崩溃。

## 实际验证

最终记录：[report.json](../runtime/competing-scenario-gateway-20261104-b/report.json)。每种故障采集7条证据，共14条，通过现有执行器 → MCP网关 → Windows Probe → 隔离采集器，再回到证据链。进程命令参数按固定身份匹配，监听PID与相应进程查询结果交叉核对；两种故障均通过。旧轮次证据在新窗口被拒绝。

两场使用相同端口、配置和症状文本，取证前的完整决策输入相同；没有预置候选、有限预期或模型检查顺序。预检中的7项固定检查仅核验场景能力，不算模型自主调查。

使用真实 `InvestigationStrategy.decide` 的输入构造，在结构化请求发送前拦截，保存初始和取证后两份输入。截取输入及工具结果均未包含已知控制器答案标记、隐藏故障标签和专用随机标记；通过日志工具读取控制器文件得到明确的 `ProbeConfigError`。连接中断不能冒充访问被拒绝。该检查覆盖本次决策输入和工具白名单边界，不宣称证明所有语义泄漏均不可能，也没有覆盖真实模型响应或完整API诊断流程。

恢复由控制器执行，随后控制器直连及Probe分别确认三个接口均为200 healthy。临时业务、网关和Probe已停止，端口释放，清理错误为0。原窗口、正式常驻Probe和用户业务不受操作。

专项回归三个文件最终共29个不同测试通过：首轮28项通过，随后新增“运输失败不得算访问拒绝”回归，并复验直接修改的预检测试文件8项通过；不累加重复测试。最小新增身份测试在修前因缺少独立身份接口失败。测试仅有既有PyMilvus弃用警告，没有运行全量、前端或付费实验。

开发中首份免费网关记录 `runtime/competing-scenario-gateway-20261104-a/` 保留；收紧访问拒绝判据并保存恢复Probe原始证据后，最终版本运行于 `...-b/`。两次均为免费固定采集，不是两次自主诊断或机制比较。

## 如何使用与判定

免费重建与验收入口：

```powershell
.\.venv\Scripts\python.exe scripts/verify_competing_hypothesis_scenario.py --output runtime/<新的专用目录>
```

实现位于 `scripts/competing_hypothesis_fixture.py` 和 `scripts/verify_competing_hypothesis_scenario.py`。后者只有免费预检入口，不能执行模型诊断。它保留故障答案、现场工具轨迹、证据ID、实际决策输入、源码哈希和恢复清理记录，控制器材料不加入Agent状态。

下一次真实单场观察应保持这套场景和取证权限，允许模型自行提出与选择检查。检查重点是：候选是否提供可区分的有效预期和参数、ID变化是否遵守条件身份、查询是否实际执行并被消费，以及报告是否命中隐藏故障位置。若仍缺候选契约或发生身份问题，直接记录，不能继续归咎于“场景不够复杂”；若候选已合格但当轮检查全部完成，则说明跨轮机制仍可能没有适用机会。

本轮没有真实模型请求，费用新增0。历史646条账本、原summary和checkpoint前后哈希一致，历史61条未知价格保留；不回填原失败结果或评分。场景准备通过不等于候选自然生成通过、诊断质量提升或机制有收益；新的真实诊断仍须有对应单场授权，不自动使用历史余额。

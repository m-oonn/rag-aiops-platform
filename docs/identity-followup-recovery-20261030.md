# 候选身份错误后的独立现场补查修复

日期：2026-10-30。**已修复运行时把候选身份错误扩大为整个调查停止的问题。错误提议仍整轮拒绝；有独立现场依据的有限补查可以继续。** 本轮不调用模型、不采集新现场、不改变原实验结果。

## 原因和实际改动

五元预实验首场第三轮中，模型把入口候选 ID 用于下游 TCP 条件。身份守卫正确拒绝了整轮候选更新。同时，现场策略已根据真实下游 TCP 失败选择 4472 监听检查，但最终 `check_error` 无条件优先采用身份错误，导致这个与错误提议无关的合法检查也被停止。

`src/agent/aiops/strategies/investigation.py` 抽出共用 `dependency_followup_policy`，复用原有两条现场策略，并在策略返回前核对范围、工具、具体参数、执行历史和检查进度。遇到身份错误时：

1. 继续拒绝整轮候选提议，保留已保存候选 ID、条件、原提议、出生步及主候选；原始模型输出留在 `model_suggestion`。已有候选仍可消费真实新观测，但不采纳错误的身份或预期替换。
2. 从有效、当前、业务范围内的证据独立生成下一检查。只允许白名单 loopback 依赖 TCP 失败后检查对应监听端口，再根据明确的依赖到服务配置映射检查进程和允许日志。模型提议的任意文件路径不会被采用。
3. 通过后续守卫且确实排入计划后才记 `identity_recovery`，记录依据 hash、选择理由、工具和参数。失败、不可用、取消的原样检查不自动重试；仍有其他合法补查可以继续。
4. 无合法独立补查时依旧停止，说明候选身份问题和未独立验证检查是否穷尽；不把补查列表耗尽写作现场原因已经查清。

没有自动修改模型 ID、没有增加模型重试、没有放宽根因门槛，也没有修改 LangGraph 路由。下一步需要的模型决策仍按原图运行；独立补查执行器直接使用已校验参数，不额外请求模型。

`scripts/mechanism_behavior.py` 同步核对：错误提议拒绝后保存的候选内容不被替换；独立策略能从同轮原始证据与此前工具失败记录重建；排入计划、实际工具、参数和成功执行相符。缺执行、失败执行、伪造来源或换参数不能通过。轨迹保存脱敏的此前工具执行记录供该核对使用，旧停止轨迹无需新增字段即可读取。

独立补查是四组共用的固定策略，单独标记，不增加保护或矛盾改向成绩。它不是第三项创新，也不保证能查明服务为什么停止。

## 验证结果

最终八文件 **332 项通过**，包含：

- 四组机制开关下，同一错误提议均拒绝、候选保持，独立端口→进程→日志补查可以继续，之后诚实停止。
- 远程依赖、对象未解析、目标不符、非允许依赖、缺工具或已有结果时不获得额外检查权限；远程证据为合法 hash 的构造数据。

- 审计的伪造来源、错误参数、候选替换、前次失败、当前执行失败和缺执行反例均拒绝。

- 既有故障 API/SSE/SQLite 刷新、调查策略及 Probe 链路回归通过。

# 同一现场四组编排的免费验证

2026-10-25。复用现有Windows单场入口，新增同一控制器环境的四组顺序编排。本轮只使用离线替代决策与文件材料，没有真实模型、新故障或服务启动停止。

## 实现与实际影响

- verify_windows_local_faults.evaluate_four_groups 在同一套端口、日志路径、Probe配置和知识语料内，按正常、下游不可达、应用错误三类场景组织四组，共12场。场景及组内顺序随机并保存；每组先恢复正常再设置场景，复用set_model_case现有清日志与现场核对。相同重置流程不表示不同时间的观测完全相同。
- 每场仍由evaluate_model_case启动新模型子进程，随机独立产物目录、runs.sqlite、checkpoints.sqlite；编排拒绝目录、thread ID复用和状态库缺失。数据库文件存在只是一道结构门槛，本轮没有真实跨进程运行验收。
- 条件hash在运行前、重置后、每场结束检查，运行来源和比较配置由已有record_integrity核对；仅两项机制开关可不同。控制器答案、顺序和结果保存在控制器文件，模型症状保持同一句中性请求；配置和知识目录不加入前组报告。
- 新run-budget-cny给每场相同预留上限，预算器同时守累计与本场额度。开始前要求累计余额覆盖12份相同上限，完整继承旧账本；不足时不开始业务重置。它是预留机会限制，不是供应商实际费用或新的付费授权。
- 发现共享网关probe_list_evidence可返回前期历史摘要，且planner会主动调用。四组模式通过isolate-history在planner/executor获得工具前移除它，保留当前现场工具和固定知识；不删除网关历史，旧模式保持兼容。record保存shared_history_enabled=false，编排实际核对。
- 任一子场流程/机械检查失败、配置变化、状态复用或异常立即停止；finally恢复正常，恢复失败独立记录。四组控制器保存完整顺序、重置、结果、错误与恢复状态。汇总检查整组完成、恢复、固定条件hash和12场对应，失败整组不生成差值。

新增four-groups CLI模式仅在显式run-model、单场额度、继承账本及已有人工smoke审核具备时进入，不能与单组覆盖混用；默认免费预检不变。这些参数是程序门槛，不代替用户付费授权，本轮没有执行该模式的真实调用。

## 下一步与理解边界

免费核对组间现场观测隔离：共享Probe采样缓存、日志窗口和baseline是否可能把重置前数据带入下一组。先用历史记录/离线替代复现并补最小门槛，不启动模型或新故障。真实同机反复重置与自主收益仍未验收，不以编排测试代替。

本次需要掌握：新进程不自动消除共享网关历史，累计上限相同不自动保证每组机会相同；独立数据库与当前现场证据是两层不同边界。系统完成离线实现与接线核验，本轮没有用户独立复现的新记录。

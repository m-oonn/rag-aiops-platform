# AIOps 优先的界面初稿

日期：2026-11-13。依据导师版《基于 LangGraph 的 AIOps 根因诊断 Agent 设计与实现》开题报告和本地当前后端源码。

## 设计结论

把系统组织为一次故障诊断的工作空间。用户默认进入诊断，先看结论和限制，再看候选、取证过程与原始记录。运维知识库提供排查参考，平台维护负责依赖与入库任务。通用聊天、助手搭建、Agents 搭建及 RAG 评测不再占据一级导航。

开题的五模块不是五个必须独立导航的页面：诊断编排、假设管理、证据工具和结论输出共同组成诊断页面；知识库与经验检索作为辅助页面，并在诊断中注明资料出处与现场证据的区别。

## 对现有功能的取舍

附件首页首先展示知识库数、文档数、待处理任务和评测任务，视觉重心落在 RAG 平台管理。AIOps 入口与会话、助手、Agents、监控平级，不能直接体现毕业设计要研究的根因诊断过程。问题在于信息优先级与功能定位，不是已有功能数量本身。

| 现有功能 | 与本题的关系 | 初版处理 | 原因 |
|---|---|---|---|
| AIOps 诊断 | 毕设主线 | 默认首页，占据首屏主体 | 能展示规划、执行、候选修正、证据与结论之间的联系 |
| 知识库与文档分块 | 开题明确模块 | 保留，改名运维知识库 | 重点是手册、故障经验和可追溯出处，数量统计不值得占据首页 |
| 通用会话 / 知识问答 | 辅助能力 | 移出一级导航，保留旧入口兼容 | 自由聊天与根因诊断的状态、证据和验收不同，混在一起会稀释主题 |
| 助手搭建 | 通用平台能力 | 本轮不进入毕设主界面 | 任意人设、提示词与版本管理并非五模块的独立研究任务 |
| 通用 Agents 搭建 | 与主题名称相似，任务不同 | 本轮不进入毕设主界面 | 通用工具调用 CRUD 不等于有候选管理和证据约束的诊断 Agent |
| 监控 / 队列监控 | 平台支撑 | 合并为平台维护的文档任务与 Worker | 此处监控的是入库任务与平台基础设施，不能被误认为业务故障监控 |
| 效果评测 / 自动生成问答对 | RAG 辅助实验 | 移出主导航；文档 QA 高级功能收起 | 当前接口测问答质量，不能证明根因诊断效果；生成题集还会调用模型 |
| 文件存储 | 基础设施 | 放入平台维护 | 个人对象文件管理与诊断研究关联较弱 |
| 账号 / 审计角色 | 必要支撑 | 底部身份入口与平台维护 | 保护诊断所有权和原始证据访问，但不应成为答辩演示主线 |
| 首页数量卡片与全部正常灯 | 主题表达较弱 | 从诊断首页移除 | 知识库数量不能证明诊断能力；平台依赖探活也不能证明业务正常 |

对于本题，多余的是通用平台功能占据的主要页面位置，以及与诊断无关的展示流程。初版不删除后端接口或历史数据；后续若要真正裁剪代码，需要另行核对调用者、数据迁移和旧入口兼容。

答辩演示应围绕同一条路径：输入异常 → 看检查过程 → 对比候选及修正依据 → 点开证据 → 阅读结论等级、建议和限制。LangGraph 的编排与假设管理通过这条路径呈现；不靠额外堆一张“AI 大屏”来突出 AIOps。

## 页面与接口对应

| 界面 | 用户任务 | 已注册接口 | 初稿边界 |
|---|---|---|---|
| 故障诊断（默认） | 提交描述、查看过程、解释结论 | POST /api/v1/aiops；GET /aiops/runs/{thread_id} | 创建参数仅 query/session_id/terminal_enabled；没有模型/预算/时间/目标的独立请求参数 |
| 候选与取证 | 对比支持、反对和待核实，跳转依据 | SSE 的 status/report/complete 中 investigation/diagnosis；GET /aiops/runs/{thread_id}/steps | 不虚构概率；步快照关闭时为空，不补造过程 |
| 证据抽屉 | 查看出处、采集时间、可用状态 | GET /aiops/runs/{thread_id}/evidence 与 /evidence/{evidence_id} | 每次受诊断所有权控制；普通用户不能读取审计原始字段 |
| 诊断前能力检查 | 确认取证来源能否使用 | GET /health/dependencies；GET /aiops/targets/{target_id}/status | 仅能读唯一配置目标；没有目标列表/创建/切换接口；Probe 缺项按未知处理 |
| 最近诊断 | 找回当前浏览器保存的诊断 ID，按 ID 恢复 | GET /aiops/runs/{thread_id} | 没有 GET /aiops/runs；初版只能本机索引，不能冒充全账号历史 |
| 运维知识库 | 建库、入库、查看分块及来源 | /knowledge-bases 的 CRUD、upload、documents、chunks、preview、retry | 检索测试 POST /{kb_id}/search 只支持 retrieval_mode=bm25；不包装为通用向量搜索接口 |
| 平台维护 | 查看平台依赖、文档任务、Worker | GET /health/dependencies、/health/queues、/monitor/、/monitor/stats | 把平台状态与被诊断业务状态分开；不把不可用绘为 0 |
| 文件维护 | 预览、下载、上传个人对象文件 | /storage 的 files/download/preview/upload/url/batch-delete | 初稿只演示结构，真实写入需正式接入；不是诊断主功能 |
| 账号与权限 | 查看身份与证据权限，管理员管理角色 | /auth/me、/auth/users、PATCH /auth/users/{user_id}/role | role=user/auditor/admin；管理员不能改自己；管理员也不能读他人诊断 |
| 终端待审批（高级） | 查看待执行命令，外部审批后续跑 | GET /aiops/runs/{thread_id}；POST /aiops/runs/{thread_id}/continue | 审批在 Termcp；页面不能用一个本地按钮替代审批；普通 pending_review 不可通过此接口继续 |

上表除首行完整路径外，其余业务路径均以前缀 /api/v1 开始。全量 78 路由、模型与参数见《接口全量清单.md》及 api-inventory.json。

## 后端核对结果与界面限制

1. **缺全量诊断列表。** 当前只有按 thread_id 读取单个诊断，没有服务端分页、筛选、搜索接口。原型“最近诊断”明确使用示例本机记录。若要跨设备历史，应新增 GET /aiops/runs 并按 user_id 限制、分页；这只是建议，本轮未实现。
2. **缺取消合同。** 现有 Vue 取消是中断前端 AbortController；不能由此承诺服务器已停止，也没有 cancel/retry/delete run 接口。原型仅有“停止演示”，不假装取消真实任务。正式页面建议称“断开进度连接”，如需真取消再定义后端状态与取消时机。
3. **缺成本历史返回。** run_details 只回 diagnosis/investigation/investigation_failure；消耗信息由诊断请求的 meter 产生，不能承诺刷新后完整复原费用，也不能把本地推算当供应商账单。初稿不放累计花费卡。
4. **没有全局服务拓扑/目标 CRUD。** 唯一目标状态可展示，依赖关系只取当前证据确实提供的内容。初稿三服务链明确为示例，不假装来自服务目录 API。
5. **部分取证能力可用不同于被诊断业务正常。** /health/dependencies 是本平台基础设施；/health/queues 是 Worker；/monitor 是文档入库。诊断源逐项展示为可用、不可用或未知，不使用一个总绿灯代表业务健康。/health/dependencies 未覆盖知识/变更所有来源，不据此宣称所有证据源齐备。
6. **两个路由模块未注册。** query.py、tasks.py 存在源码但未挂载。历史上传实际路径为 /api/v1/upload/upload；保留兼容，前端入库统一走知识库 upload。
7. **问答评测不是根因诊断实验。** /evaluations 不提供 AIOps 对照/消融实验结果。初稿不造“诊断准确率”，实验材料继续由既有脚本和审核文档承担。
8. **页面按钮不能越过证据守卫。** 候选按后端状态展示；没有可继续检查时展示缺口和停止理由。终端仍使用外部授权。
9. **普通用户只看受控证据。** 原型默认普通用户；切到 auditor/admin 仅演示可见字段差异，不是前端实现授权。正式权限以服务端 can_read_raw 和证据详情响应为准。
10. **MCP 由后端调用。** 全量清单补充独立网关 HTTP/WS 与显式 MCP 工具，不把它们暴露成浏览器直接访问的 REST 操作。SDK 构造的 /mcp 传输路径不与主应用业务路由混计。

## 信息层级与视觉

- 一级导航只保留故障诊断、最近诊断、运维知识库；平台维护放到底部。
- 首屏主体是当前诊断：任务描述、结论等级、关键依据和待处理事项。右栏呈现取证来源与服务关系，避免把数据库/缓存/Worker 抢到首屏中心。
- 详情以“结论报告、排查过程、候选原因、证据台账”切换；用户无需从长页面中寻找结论。
- 蓝色用于行动与当前步骤；绿色仅用于已经明确的状态；橙色表示待核实/来源缺失；灰色表示未知，颜色同时附文字。
- 不显示未经校准的候选概率、不显示伪造的准确率和节省时长。不同结论等级以文字和证据条件解释。
- 移动端导航折叠、双栏变单栏、表格保留横向滚动；证据用独立抽屉，键盘可关闭。

## 原型可操作内容

原型使用自编的演示场景，**不是任何已落盘真实模型运行的重现**。页面角标、场景选项和诊断记录均注明示例。提供停机、配置可疑、延迟待核实、终端待审批、执行失败五种状态。可切换导航/报告标签、展开证据、切换演示角色、复制报告、按条件筛选最近记录、预览知识文档、模拟本地文件登记以及搜索 78 个后端接口。

最近记录、角色和本地文件登记仅保存在当前页面内存；刷新后恢复内置示例。建库按钮只展示现有创建接口合同，不创建真实或模拟知识库。

新建诊断只在本地按预设场景演示状态变化，不访问产品 API、不连接模型、不修改项目数据库。上传只读取浏览器所选文件的名称和大小，不上传或解析。知识检索使用本地固定片段演示，不冒充后端检索。原型不提供真实删除动作。

实现前先评审原型。本轮仅新增此目录的设计和原型文件，不修改 Vue、后端、论文正文或既有用户改动。

## 正式实施的最小顺序

1. 调整导航和默认路由，保留旧路由兼容；不先删表和接口。
2. 复用当前 SSE/恢复/证据实现，整理诊断页面，完整处理 error、pending、来源 unavailable 与空快照。
3. 最近记录先按用户隔离保存本机 ID；只有需要跨设备时才补服务端列表。
4. 合并平台维护入口，知识库保留现有入库能力；助手、Agents、RAG 评测藏入旧版工具入口。
5. 逐项对照导师版五模块截图与报告术语，再更新论文实现说明。

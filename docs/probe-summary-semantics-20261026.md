# Probe 摘要状态与错误边界

2026-10-26，在 `main` 当前工作树完成。此前前端把所有 `error` 都称为“采集错误”，但 Probe 的真实字段包含“当前对象不支持”“事件通道未配置”“权限不足”“部分进程不可读”等不同情况。摘要因此增加 `status`，把检查是否适用、是否完整与业务现场是否正常分开。

## 调用链与判定

数据从 Windows collector 的固定 `payload` 开始，经 `validate_tool_evidence` 校验目标、操作、时间、hash 和截断状态，再由 `evidence_index` 关联证据ID，进入 `_evidence_summaries`。`_probe_summary_status` 只按已校验字段判定覆盖状态：

| 状态 | 判定依据 | 含义 |
| --- | --- | --- |
| `observed` | 检查成功，未标截断或已知缺项 | 可用于描述本次有限现场，仍不等于原因已确认 |
| `partial` | Probe 标截断，资源含不可读磁盘，或进程存在跳过/内存/CPU 不可用计数 | 只能使用已经返回的部分内容 |
| `unavailable` | 操作返回其他顶层错误，如权限或采集适配器不可用 | 本次检查不可用，不能据此认定对象正常或异常 |
| `not_applicable` | 服务状态显式为 `not_applicable`，或事件日志明确未配置通道 | 当前对象不支持该检查；应换用适用的进程、端口或入口数据 |

`dependency_probe` 的 TCP 状态和 HTTP 子检查分别保留。例如 `TCP failed, HTTP unavailable (URLError)` 仍是 `observed`：TCP 失败是本场实际观测，HTTP 未取得不能抹掉已有事实，也不能推出下游停止原因。

摘要仍只包含证据ID、操作、对象、采集时间、简短文字、状态、截断和受限错误文本，不包含原始 payload。新增字段会写入调查记忆，后续模型能够看到覆盖状态；这不改变调度和结论门槛。

前端按状态显示“检查不适用”“结果不可用”“仅包含部分结果”，旧 checkpoint 没有 `status` 时继续按 `error`/`truncated` 兼容。新增字段不改变原始证据、原文读取权限或人工处理建议。

## 验证

- `tests/test_aiops_events.py` 31项通过。参数化覆盖服务不适用、事件通道未配置、端口权限不可用、资源部分磁盘不可读、进程部分不可读、依赖 TCP/HTTP 分离及日志截断；另有反例确认错误文本不泄漏原始响应。
- 正式固定决策输出链路24项通过，当前历史故障的摘要确认包含 `status=observed`，原有故障发现与人工审核边界不变。
- 调查融合与 Probe 调查流程42项通过。
- 前端全量18个文件108项通过，独立目录 Vite 构建通过。组件测试覆盖四类状态、旧字段兼容、错误文本转义、缺失引用和“不获取原文”。
- 既有 PyMilvus 4条弃用警告是原先存在的环境警告，本轮没有引入新失败；后端全量、真实模型、在线 embedding/rerank 和浏览器复验本轮未运行。

## 真实材料只读回放

`runtime/probe-summary-semantics-20261026-a/real-probe-replay.json` 只读消费 `runtime/free-demo-20261026-a/controller/evidence.json`。19个既有场景共48条当前观测，操作分布为30条依赖探测、11条文本日志、3条 inventory、2条进程和2条端口；48条全部为 `observed`，没有新增观测或模型调用。

这同时验证“业务异常不等于采集异常”：端口冲突、HTTP 503、TCP 失败、应用错误日志和进程列表仍作为现场事实保留，没有被归入 unavailable。部分或不可用状态由与 collector 字段一致的测试夹具覆盖；本轮没有为了制造这些状态而启动新服务或注入故障。

## 限制与下一入口

常驻 API 8200 未重启，因此不能宣称现有常驻服务已经发送新增 `status`；5273 前端读取当前工作树。既有历史材料没有回填该字段。四类状态还需要用正式 SSE、隔离浏览器、刷新恢复和证据ID定位做一次串联验收，确认页面文本、路由事件和旧 checkpoint 兼容一致；继续暂停真实模型、付费调用和新故障。

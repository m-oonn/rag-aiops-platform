# 下游进程与日志补查验收（2026-10-29）

本轮落实“能查的继续查，未查清的说明具体原因”。专用下游原来只有依赖探测白名单，没有进程和日志服务映射；两个业务共用 app.log，按 python.exe 查询也会混入其他进程。

## 实现与调用链

- Probe 服务配置增加可选 process_args：进程名称匹配后，精确匹配连续 argv 片段。专用业务使用各自 --mode-file 路径区分上下游，重启后不用回填 PID。命令行只在本机比对，不进入采集结果或评测参考目录；不可读或空命令行计入 skipped_count，不能作为进程不存在的证据。旧配置保持按进程名匹配。
- BusinessService 增加显式 dependency_services。业务依赖、配置映射和实际 inventory 服务白名单必须同时满足；别名同名本身不授予权限。评测入口明确建立专用业务关系。
- 控制器分别生成 app.log、downstream.log，重置分别清空。控制文件没有作为 Agent 工具数据提供。
- 策略沿既有失败 loopback 依赖监听检查，继续选择映射的进程快照和具体白名单日志。保留原始 model_suggestion，使用 policy_selected_check 约束执行器参数；不把这项共同检查计为假设保护或矛盾触发。四组使用相同规则。已有返回不原样自动重复；同参失败保持具体原因，仍允许其他合法检查。
- 报告区分映射缺失、工具未加载、进程配置缺失、查询失败/不完整、空日志、日志已读但因果未验证、事件通道未配置。远端依赖不能借本机映射执行本机进程检查。文本通配路径不自动枚举，须配置具体允许文件或由现有合法检查提供实际路径。

调用链：src/probe/windows/config.py、collector.py → target_catalog.py → InvestigationStrategy → executor 既有权限与参数校验；控制器、评测目录和免费固定决策图验证同步更新。未增加 MCP 工具、依赖或任意配置文件读取能力。

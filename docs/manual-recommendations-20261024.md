## 实现及边界

正式调查链路仍由 InvestigationStrategy 的共享裁决决定继续检查或停止。仅当结果为 localized_fault 时，从当前、范围内、完整且已经通过 Probe 校验的确定性故障观察生成建议；引用及关联引用再次匹配原文。建议是有限模板，不消费模型自由文本作为操作指令，也不把手册建议当成本次现场事实。

- HTTP 失败：核查同一应用、请求时间窗口的日志及近期变更；确认相关配置或代码异常后，由人修正或回退。仅凭 HTTP 失败不能认定配置错误或下游故障。
- TCP、进程、服务或监听异常：核对业务对象与进程、监听和配置，确认后由人恢复或修正；无法由连接失败推断进程退出原因。
- 端口归属冲突：同时引用监听记录与服务 PID，先核实程序和影响；不能直接终止未知进程。

每项包含 scope、evidence、action、preconditions、risks、verification_steps；origin 为 verified_observation_template，status 为 manual_review_required。操作前重新采集状态、确认权限并准备配置备份与回退。报告和页面明确“尚未执行、不作为根因证明”。未定位及健康结果不生成操作列表；正常未定位停止报告说明暂不给具体修复操作。结构化模型输出异常的既有停止报告仍保留未完成说明，不伪装成正常建议输出。

新增 src/agent/aiops/recommendations.py；在 strategies/investigation.py 的 diagnosis_result 生成结构化建议，停止报告消费同一列表。已有 service、事件和 checkpoint 透传整个 diagnosis，无须另加表或 API。Vue AIOps 页面兼容旧记录缺少 recommendations，新增人工建议区及沿用原权限的证据按钮；不提供执行修复按钮。

通用模板不会自动给出“修改 max_attempts”一类根因专属操作，建议的业务适用性仍需人工核对。观察原文节选无法匹配时不生成该建议；没有绕过引用门槛。

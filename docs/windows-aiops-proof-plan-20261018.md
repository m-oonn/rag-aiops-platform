# Windows AIOps 可用性证明与验收方案

日期：2026-10-18。适用分支：`codex/termcp-aiops-integration`。

## 1. 要证明的结论

最终要证明：用户只描述症状，Agent 能自主选择已授权检查，根据真实现场证据改变调查方向，给出与实际故障一致且可追溯的结论；证据不足时承认未定位，且不会越权操作。

分别验收“采得到数据”“会自主调查”“根因判断正确”“权限和恢复可靠”。单元测试通过、工具调用成功、报告有文字，均不能单独代表最终目标通过。有限测试只能证明指定场景，不能推出所有生产故障均可定位。

## 3. 本机验证环境与边界

无需另一台 Windows 机器即可先验证应用级故障：在 `127.0.0.1` 启动专用测试应用、模拟下游、临时日志、网关和临时 Probe。仅停止本轮创建且核实PID的测试进程；不得操作真实业务进程或既有监听端口。

- 使用独立配置、token、数据库、证据目录和随机运行ID，不覆盖正式配置或资料。
- 清理仅处理本次明确创建的进程和文件；结果保留到独立 `runtime` 目录。
- 不修改防火墙、注册表、真实服务，不填满磁盘或制造整机高负载。
- 不自动启用 Docker，不扩大常驻 Probe 白名单，不读取未授权业务日志。
- 当前账户临时 Probe 通过，不代表 LocalService 能读取业务日志；两种身份分别记录。

真实 Windows 服务停止、持续CPU压力、磁盘不足等系统级故障留给隔离目标。用模拟数值可以验证规则，不能冒充这些系统级故障已在现场复现。

## 4. 验收步骤

### A. 独立核对现场数据，不调用模型

通过 Probe 读取资源、配置服务、进程、端口和白名单日志，同时用独立本机只读接口核对同一时间附近的数据：服务名与状态、测试PID、监听端口、测试日志标记必须一致。CPU瞬时值允许随采样波动，必须记录采样窗口和统计口径，不能要求与任务管理器某一帧完全相等。

检查目标ID、采集时间、操作、hash、截断及权限不足标记；两条基线时间递增。断线后显示 offline，旧数据标为 historical/stale，不能继续支持当前确定性结论。

已有免费入口：

```powershell
& .\.venv\Scripts\python.exe scripts/verify_windows_probe_readonly.py
& .\.venv\Scripts\python.exe scripts/verify_windows_runbook_retrieval.py
& .\.venv\Scripts\python.exe scripts/verify_windows_local_faults.py --evaluation-preflight
```

三者分别覆盖本机直接采集、本地手册检索、临时故障完整流程，不能互相替代。常驻服务额外使用 `verify_installed_windows_probe.py --executor-batch`，前提是已有匹配配置的可用回环网关；该脚本不负责启动网关。

### B. 真实模型未知答案调查，先跑现有两场

现有入口：`scripts/verify_windows_local_faults.py --run-model`，实际调用 `scripts/evaluate_windows_probe.py`。执行前核对当前模型、价格、累计费用账本与有效授权，不因重试重置额度。当前脚本仅包含“正常”和“下游不可达”两种随机排序场景。

控制器保存真实场景、变更时间与恢复结果；模型只收到相同的中性症状及允许的服务/依赖目录。不得把场景名称、预设答案、控制文件路径或前场日志交给模型。保留模型实际输入、工具记录和知识检索记录，事后检查是否泄题；顺序随机本身不足以证明无泄题。

| 场景 | 实际现场 | 合格结论 |
| --- | --- | --- |
| 正常 | 入口和依赖TCP/HTTP均正常，未出现对应错误 | 仅声明已检查范围正常；不能虚构故障，也不能宣称整台机器或所有业务健康。 |
| 下游不可达 | 入口TCP仍通但HTTP503；配置下游TCP失败；同期应用日志记录上游连接失败 | 将故障定位到配置依赖不可达导致入口异常，检查入口自身退出等替代解释；不能进一步断言数据库崩溃、密码错误或网络设备故障。 |

必须由真实模型自主选择工具和后续检查。固定模型、预设检查序列、直接向模型提供答案，都不计为本项通过。知识检索允许模型自主选择；未调用就明确记录“本场未验证知识利用”。

脚本现有 `workflow_completed=true` 只表示流程结束，`diagnostic_correctness_verified=false` 必须保留，直到人工对照场景和证据完成裁决。报告“未定位”是诚实结果，但不计故障定位成功；费用耗尽或无最终报告记为未完成。

### C. 扩展反例，验证不是看到503就猜下游

两场通过后再扩展真实模型场景，新增场景计入对应授权和费用：

1. 应用自身返回500/503、下游仍正常：应转查应用日志，不能归因下游不可达。
2. 专用应用进程退出、下游正常：应结合PID、监听端口、入口探测和日志定位到应用不可用，不能把退出的深层原因硬猜出来。
3. 专用测试端口冲突：端口归属和启动错误共同支持才可确认；仅看到端口有PID不够。
4. 拒绝读取关键日志或依赖证据：应报告缺失和未决解释，不能绕过白名单或输出无证据的确定根因。

这些场景的免费采集基础已有部分实现；现有付费两场编排尚未覆盖它们，不能声称只加运行参数就能完成全部模型验收。

### D. 安全、权限、恢复与正式页面闭环

- 错token、错误target、越界日志/依赖、任意shell方法均拒绝。
- 修改或过期的证据不得支持确定性结论；知识手册不能充当现场证据。
- 普通用户只能查看自己的运行和脱敏摘要；审计原文读取单独检查角色及运行归属。
- 首先验收待审批恢复：经正式HTTP接口创建待审批运行，退出专用测试API进程，启动第二个进程，用同一用户继续同一thread，核对审批、证据和后续执行无重复；跨用户继续必须拒绝。当前只有同一进程内服务对象关闭并重开checkpoint的测试，尚无此跨进程验收记录。测试若替代Termcp和模型，必须明确只证明持久化与恢复接线。
- 普通调查正在运行时崩溃后恢复是另一项能力。当前继续接口仅支持待审批状态，不能凭SQLite checkpoint宣称任意调查步骤均可跨进程续跑；需要另行实现恢复入口、幂等和执行重放边界后验证。
- 从正式AIOps页面提交症状，观察工具执行和证据时间线，再核对最终报告引用。直接调用图的脚本通过，仍需这一项才算用户入口闭环。
- 高风险审批另走现有Termcp回归；Probe只读不等于已经证明Termcp审批流程通过。
- 退出时本轮专用进程已结束、端口已释放；真实业务和常驻配置未被改动。

正式Compose、跨部署TLS和真实业务接入分别验收，不能用回环网关替代。真实业务接入至少需要已登记服务名或URL、授权日志、允许探测的依赖及LocalService读取权限。

## 5. 每场交付什么、怎样判定

每场至少保存以下材料，敏感材料放受保护目录，分享前脱敏：

1. 代码版本与工作树差异指纹、模型及工具版本、配置摘要、身份和开始结束时间。
2. 模型实际收到的症状与参考资料；独立保存、调查后才揭晓的场景答案。
3. 工具调用顺序、受限参数、耗时、错误，以及原始脱敏证据、target、时间、hash和截断状态。
4. 最终报告的“结论 → 支持证据 → 替代解释 → 尚未证实部分”对照表。
5. 费用累计账本、终止原因、环境恢复及进程/端口检查。

判定分开列出：流程完成、场景定位正确、引用可追溯、替代解释覆盖、边界合规、环境恢复。任何越权或把伪造/过期资料当现场证据都是边界失败；结论错误就是诊断失败，不能用流程成功掩盖。

报告样本数及逐场结果，区分“成功定位”“正确报告未定位”“误报/错因”“未完成”。首轮两场全通过只算最小能力证明，不报告生产准确率。重复盲测验证稳定性时保留全部失败和费用，不挑选好看的结果。

## 6. 推进顺序与剩余距离

先复用免费现场核验与流程检查，再做现有两场真实模型盲测，随后补相同症状不同原因及证据不足反例，最后完成正式页面、应用级恢复和一个真实业务对象的接入。

当前有真实采集和流程证据，仍缺最新修复版本的真实模型正确性裁决、反例覆盖、真实业务配置及正式部署闭环。不能据此给出可信的完成百分比或宣布已经达到生产运维能力。

本方案整理本身没有调用模型、注入故障、启动服务或更改本机配置。

## 7. 一轮可以当面核对的验收

1. 免费核验：使用独立目录和随机运行ID，记录专用应用的PID、端口和启动时间；从Probe查询，再用独立操作系统接口核对。不要仅用同一采集器核对自己。
2. 免费故障准备：专用回环应用与下游分别运行，验证正常、下游不可达、应用自身异常和应用退出后的证据确实不同；每场结束恢复并检查端口。本机不停止真实服务、不制造整机CPU或磁盘故障。
3. 有效费用授权后，先跑现有正常/下游不可达两场真实模型调查；模型只收到症状和允许对象，自己决定工具和顺序。其余反例需先补模型场景编排，再纳入费用和样本范围。
4. 调查后揭晓控制器保存的答案。逐场列出预设事实、Agent结论、引用证据、替代解释、越界行为及结束原因；正常场景虚构故障、把应用错误判成下游失败、无报告或耗尽费用，均不能计定位成功。
5. 从正式页面新建一次诊断并观察实时证据与最终引用；`runtime/aiops-browser-56c45b9d703c49cc952c5eb20c821e9e` 已用固定替身验证真实 Edge 登录、页面提交、SSE 完成和证据时间线。该记录不替代真实模型根因归因验收。
6. 单独验证待审批的两个API进程恢复及真实Termcp UI裁决，不把固定替身测试计为实际终端审批完成。

交付每场脱敏证据包与判定表，保留失败记录。首次完整通过只能说明所测场景可用；要声称稳定，需对不同顺序与数据重复盲测，并报告全部样本数和失败数。此前模型账本已触发预算停止，保守预留额不是实际账单；本方案不启动新付费调用。

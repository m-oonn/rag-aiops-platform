# 已查结果、未决问题与可用来源：离线交付

2026-11-04。本轮完成下一次模型决策输入的整理：程序在请求前把已有问题、检查、现场结果、拒绝原因和来源配置放进同一份 `decision_agenda`，让模型先消费结果，再决定换查还是保留未知。真实模型是否更会收束尚未验证；本轮没有真实模型、工具或新现场调用。

## 范围与实现

生产修改仅在 `src/agent/aiops/strategies/investigation.py`，复用现有调查节点、候选、进度计算、通用补查、权限与重复查询守卫。没有新增服务、节点、公开 API、依赖或自动纠正请求；`probe_checks.py` 与实施前 hash 一致。没有扩展条件类型、编造因果规则或调整诊断通过门槛。

每次已有决策请求前，程序从当前有效且在业务范围内的证据重新计算：

- 已保存检查对应的问题和预期、实际结果、证据ID，以及当前查询是否通过原有守卫；主检查、候选检查和现有通用补查分别保留来源。失效、过期、被有限观测反驳或范围外的候选不会被标为可延续。
- 文本日志的实际返回行数、请求行数、最多三条且每条最多400字符的原文节选，以及节选是否缩短、结果是否截断。明确只覆盖本次允许文件的尾部返回内容，不能称为完整历史或独立因果证明。
- 事件查询的返回数量、时间窗、通道和截断状态。空结果不等于没有停止事件，更不能据此确认发起者。
- 当前有效 inventory 中、允许服务的文本日志、事件通道和配置快照来源。来源配置与工具是否加载分别记录；配置缺失、未加载和未知保持区别。`configured` 只说明有配置，不保证有记录或能回答历史归因。

`query_eligible` 是请求前的有限查询核对，不保证该检查必然被选择，也不确认问题已解决。模型可以提出清单外的新具体检查，仍须通过原有身份、范围、参数、失败和重复守卫；没有使用固定菜单代替自主调查，也不声称实现了通用信息增益或因果语义判定。

新清单只沿用已保存的未决问题ID，没有对应ID时留空，避免模型照抄一个新生成ID后被现有守卫拒绝。模型投影中的检查参数与进度集中保留在清单，候选通过引用关联；相同选项合并来源。完整候选、检查进度及审计历史继续按原格式持久化，公开返回与旧 checkpoint 格式不变。没有状态参数的旧投影调用保留原有读取路径。

提示规则要求模型分别说明：证据来源缺失、检查执行受阻，或没有提供有效检查方案。程序不会从自然语言猜测“谁停止”，也不会在来源缺失时强行拼出根因；实际结束仍由现有停止前复核与报告路径完成。

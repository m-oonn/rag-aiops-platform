# 组间现场观测隔离的免费核对

2026-10-25。针对四组控制器的下一步风险，核对 Probe 采集进程、网关缓存和测试业务日志是否会把重置前数据带入下一组。

## 发现

- `collect_isolated` 每次检查启动独立 worker；当前工具请求不会直接复用 baseline。网关仍保留 baseline 和历史摘要，因此四组已通过 `isolate-history` 移除 `probe_list_evidence`，避免规划器读取前组历史。
- Probe 证据原有门槛只有目标、hash 和全局新鲜度，不能证明事件或文本日志内容属于本次重置。`event_logs` 的采集时间可能是新的，但事件时间可能较早；文本日志可能包含旧行。

## 实现

初版将边界设在重置核验后；后续源码核对发现，核验请求本身会写本组日志，导致误拒绝。现已改为每组重置开始前记录带时区的 `observation_not_before`，同时独立记录重置核验完成时间。模型子进程收到边界并写入评测记录。Probe 顶层 `collected_at` 不得早于边界；事件日志时间和专用 JSON 文本日志每行 `at` 必须在边界与采集时间之间。无法解析为带时间的文本行会被拒绝，原始工具返回仍保存在脱敏轨迹中，失败证据不计入有效现场。

共享校验位于 `src/probe/evidence.py`，评测包装器和记录审核复用同一规则。记录审核读取原始返回并以原工具结束时间检查新鲜度；控制器与汇总器核对实际子进程边界和重置边界一致。边界是每场运行元数据，不参与固定条件比较。旧历史记录只读保留，缺边界不能通过新四组门槛。

## 免费验证

新增三个离线反例：旧顶层 Probe 观测、旧事件日志行、旧 JSON 文本日志行均被拒绝，轨迹保留且不标记为有效现场。相关评测、四组编排、汇总、Probe 证据和采集器测试共 291 项通过，保留既有 4 条 PyMilvus 弃用警告；未启动服务、未制造故障、未调用模型。

## 限制与下一步

后续现场核对已完成：新增 `scripts/verify_probe_observation_boundary.py`，复用真实测试业务、独立 Probe worker 与 MCP 网关。两次运行分别保存在 `runtime/probe-boundary-live-20261025-a` 和 `runtime/probe-boundary-live-20261025-b`，每次两轮正常业务重置；最终 b 版验证旧依赖观测和新采集的旧日志被拒绝，新依赖观测与核验请求产生的新日志通过。每次记录7条观测（就绪1、旧依赖2、重置后依赖/日志4）；拒绝的日志原文另存工具轨迹和 pre-reset.log，不将重复读取算独立效果样本。

最终九文件298项回归通过，结果 `runtime/probe-boundary-20261025-final.xml`；包含边界晚于重置开始、子进程边界不一致、标记有效但原文越界、未来日志及缺时区反例。既有4条PyMilvus弃用警告，早期测试与最终结果重叠不相加。临时进程停止、端口无监听；常驻8200/8105/5273的PID分别仍为4024/18136/16004。无模型、embedding、重排调用，无故障注入，无主服务重载，无提交推送。

正常业务连续重置的文本日志与探测已现场验收；未实际读取Windows事件日志，未验证故障场景下完整四组连续重置，不证明自主诊断收益。后续已接入完整免费控制器并核对失败留痕/清理，见[完整控制器边界预检](controller-boundary-preflight-20261025.md)；真实模型四组实验保持暂停。

# 错误下游地址：根因门槛与单场真实复测（2026-11-05）

## 结论

已打通 edge 业务入口的正式目标解析、现场取证和一次真实模型测试。模型在中间调查轮次提出了 `configured_downstream_endpoint_mismatch`，将 localapp 实际加载端口 5889 与登记 downstream 端口 5887 对照，并引用了配置、探测和请求日志。最终诊断仍为 `localized_fault`，没有通过完整根因验收；没有第二次模型调用。

本次可验收的直接原因范围是：localapp 本次业务请求连接其启动加载的 5889 端口失败，而登记的 downstream 在 5887 正常服务，导致请求返回 503。配置何时过期、旧端口是否曾经有效及变更者/动机仍未知，不作为本次直接原因结论。

## 免费改动与验证

- `business_catalog()` 现在逐项登记配置中的业务入口；edge 解析为 edge，并按已配置的 Probe 服务和依赖映射出允许检查范围。
- `localapp_upstream` 是配置依赖而非独立进程，已显式映射到 localapp 服务，以便依赖异常可用 localapp 的进程与日志证据核查。该映射补丁在本场真实运行之后加入，仅通过离线回归，未纳入本次实测结果。
- endpoint 环境验收不再手工构造 `target_resolution=resolved`，改为加载真实 Probe 配置并调用 `resolve_target()`。另加正式 planner 回归：edge 可进入模型计划，未登记目标在模型调用前返回 `unlocated`。
- 为唯一直接原因码增加严格证据门槛：必须同时具有加载配置快照、配置端点失败探测、登记端点成功探测、与配置哈希匹配的 localapp 失败请求日志，以及相同 request_id 的 edge 503 日志；模型须填写原因码并引用全部证据。其他自由文本原因仍不能升级为 `confirmed_cause`。

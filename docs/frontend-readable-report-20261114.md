已将正式前端报告改为短结论、故障影响图和下一步操作。沿用浅色、分隔线布局，不增加卡片；证据和完整报告按需展开。本轮仅改展示层及前端测试，没有重新执行付费诊断。

## 用户现在看到什么

- 首页一句话说明结果。本场为“下游服务停止，业务请求失败”。
- 三步图说明影响过程：下游服务收到停止请求后退出 → 业务应用无法连接下游 → 访问入口的用户请求失败。每步可点击进入对应真实证据。
- 处理建议显示简短操作标题，明确“尚未执行”；展开可查看原始建议、操作前确认、影响及恢复后检查。
- 未查清的问题、服务关系、完整技术报告折叠保留。长请求编号、进程号、配置指纹和内部字段退出默认首页。
- 候选区分“已确认原因”“有证据支持”“已排除”“待验证”；已丢弃的候选归入“此前排查”，显示“已停止排查”，不等同于已排除。
- 默认选中最终确认的原因，首先显示三份关键日志依据，其余五份依据可展开。所有引用按证据编号去重，来源弹窗沿用全局编号。

## 证据边界

前端读取后端结论，不自行升级诊断等级。三步影响图当前覆盖 `downstream_stopped_after_request`：只使用结论已引用的日志，应用与下游需要同一目标和明确调用映射，入口与应用还需要同一请求编号。缺失的步骤不补造；未确认原因保留不确定性。

另外两种后端已有原因码（错误下游地址、配置值被拒绝）提供短标题，尚未新增对应的三步影响图。原始报告、候选解释、日志及其定位信息保留。仅有旧版文本报告时使用中性“诊断结果”，不会直接显示未定位。

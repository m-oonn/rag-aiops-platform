# 问题与检查交接后的单场真实验证

2026-11-04。用户要求“真实测试，并且过程中依旧记录问题”。本轮只执行一场受控停止故障，结果为**真实验证未完成**：模型主动选到了下游停止日志，但随后的阿里云请求等响应头约60秒后超时；未知用量守卫阻断了官方兜底和后续调查。未追加第二场。不能据此判断新交接机制改善了自主调查，也不能把失败归因于场景没有原因日志。

## 范围与免费检查

沿用独立 edge → localapp → downstream 进程拓扑、正式诊断入口、Probe Gateway/MCP、G11及 candidate-opportunity 输入。控制器使 downstream 接收已有 stop-file 请求并正常退出；模型只收到业务症状、正常拓扑和允许采集的现场证据。默认规则报告，没有额外报告模型请求，没有改变提示或机制后混入补跑。

首次免费预检发现调用方仍读取已从实时投影移除的 `candidate_check_progress`，触发 KeyError。原失败保存在 `runtime/question-check-live-20261104-a/preflight/report.json`，当时0模型调用，恢复和清理通过。唯一关联脚本修复是 `scripts/verify_competing_hypothesis_scenario.py` 改读 `decision_agenda.checks[*].progress`；原证据消费断言保持。

修后相关回归 **27 passed**；正式免费预检两原因、18观测、model_calls=0，通过旧窗拒绝、当前日志、身份与答案隔离、结果消费及恢复清理。免费两原因固定检查不是两场自主调查。修后预检保存到独立 `preflight-current/`，不覆盖原失败。

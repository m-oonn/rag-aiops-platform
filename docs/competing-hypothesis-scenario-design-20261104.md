## 场景草案：同一入口503，两种故障层

搭建仅供测试的稳定入口代理 `edge`，对外始终返回相同症状：HTTP 503。代理后有 `localapp`，localapp再访问 `downstream`。每个四组块只注入下列一种真实故障，场景答案由控制器单独保存，不提供给Agent：

| 隐藏故障 | 同一入口表现 | 可区分现场条件 | 区分检查 |
|---|---|---|---|
| localapp进程未运行或未监听 | edge HTTP 503 | `processes/localapp: process_present == false`，或 `ports/<localapp端口>: listening == false`；downstream正常 | localapp登记身份对应的进程/端口，再探测downstream |
| downstream不可达 | edge HTTP 503 | `dependency_probe/downstream: tcp == "failed"`；localapp进程存在且端口监听 | 探测downstream，再核对localapp进程/端口 |

以上是候选实验夹具，不是现存业务拓扑。代理必须保持运行并把两类后端故障映射成相同503；控制器须证明注入状态、每种故障的恢复、两个版本的Agent可见输入一致，且工具只能读到实际现场。若不能做到这些，不进入模型门槛验证。

## 机会如何判定

保护机会必须来自自然轨迹：Agent曾提出一个合理候选；之后候选未出现在新提议中，但仍未被反证、未过期；它仍有一个合法、未执行且可区分解释的具体Probe检查。只存在多种自然语言原因，或保存检查已完成，不算机会。

矛盾机会必须来自自然轨迹：Agent先给出一个可由现有条件schema表达的必要预期；实际新证据经现有守卫验证后与该预期相反；机制开启后选出的具体检查与原拟检查确实不同。仅产生机制事件而计划、参数相同不算行为差异。

有效结果都须记录完整链条：`原候选/预期 → 新证据 → 原拟检查 → 机制选择 → 实际执行 → 结果被后续决策消费`。故障答案对测试人员可见，但不注入Agent输入、模型候选或预设检查顺序。

## 免费门槛与停止条件

当前Schema已经能表示两种现场预期：localapp进程/监听状态、downstream TCP状态；对应对象与字段见[调查条件模型](../src/agent/aiops/strategies/investigation.py)。新增的[本地拓扑夹具](../scripts/competing_hypothesis_fixture.py)及[回归](../tests/test_competing_hypothesis_fixture.py)已证明两种故障对edge呈现相同503和响应体、控制器侧后端状态可区分，且退出后端口释放。随后使用现有`WindowsCollector`和临时`ProbeConfig`直接读取入口状态、localapp监听端口及downstream TCP：证据能区分两种故障，序列化结果不含控制器`hidden_fault`答案；专项测试为`2 passed`，条件策略既有回归为`6 passed`。这验证到采集器层，不等于正式Probe网关链路或Agent可见输入已验收：夹具尚未经网关传输，进程身份筛选也未验证，控制器到模型的全链路答案隔离仍未证明。

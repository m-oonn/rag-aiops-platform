2026-10-25。将独立边界验收接入 `verify_windows_local_faults.verify(..., evaluation_preflight=True)`，继续使用免费路径。

## 实际改动

- `verify_boundary_rounds` 复用调用者的真实 MCP 工具、日志及 `set_model_case`；两轮均先获取旧观测、拒绝旧日志，再恢复正常业务并核对新探测和非空新日志。独立脚本与完整预检复用此实现。
- 每轮保存边界、核验完成时间、原始返回、拒绝轨迹和重置前日志。异常保存失败报告并向上传播，完整控制器不继续后续场景验收。只接受时间越界导致的预期拒绝；目标不匹配、连接异常不能冒充成功。
- 新 `cleanup_owned` 逐个处理本轮拥有的进程。某个 stop 失败后继续清理其余进程，分别记录异常；无法检查监听时保持未知且不声明端口已释放。控制器和独立脚本均使用它。

## 边界和下一入口

完整预检的真实故障流程、固定决策调查、边界检查是不同验收。当前边界子流程只对正常业务做两轮重置，不能据此声称三类故障的完整四组连续运行已验收，也没有验证Windows事件日志。清理失败分支由离线替代验证，真实受控异常时清理成功。

下一步免费核对正常、下游不可达、应用错误三类场景的实际重置与观测窗口，复用相同控制器及原文校验；不运行自主模型、不把固定决策触发当机制收益。用户本轮无需重复概念问答：关键是区分预期拒绝、业务故障、控制器失败和清理失败。

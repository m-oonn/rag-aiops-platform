# 当前方法与实验草稿：受证据约束的 AIOps 调查与机制对照

核对日期：2026-10-25。适用对象是当前工作树的自主调查链路；Git 基点为 main / 830a0da，包含尚未提交的实现，不能只用该提交号复现当前状态。本文件是可继续编辑的论文正文草稿，不是最终论文或自主效果验收。旧稿保留供追溯，核对差异见 [核对记录](../thesis-method-experiment-audit-20261025.md)。

## 写作定位与第一章衔接

本文面向本机专用测试业务的应用级故障调查，研究两个具体问题：候选原因尚缺早期支持时如何避免过早丢弃；领先候选的可核查预期遭到新现场证据反驳时如何调整下一项检查。研究贡献限定为有限假设保护与矛盾触发调度。系统集成、证据审计、PDF 知识辅助和页面展示用于实现与验证上述方法，不另列为新增算法创新。

研究目标是自主选择检查、定位有证据支持的故障对象或故障层、解释证据与限制并提出人工处理建议。未知的深层原因允许保持未定位。当前裁决没有自由文本因果验证能力，不能把运行结束、引用存在或候选得到支持写成根因已经确认。

相关工作部分可以讨论 ReAct、规划与再规划及 Pi 的工具事件和上下文设计，但须另行复核文献原文及项目版本。本文不据现有草稿断言其他系统都没有审计能力、不支持改向或只能线性执行；也不将 Pi runtime 迁移、多 Agent 或自动修复纳入当前贡献。

## 第二章 任务定义与系统基础

### 2.1 调查任务与信息边界

用户提交症状、允许调查的业务对象和配置范围。Agent 根据已有信息提出候选解释与检查，工具在原有权限和参数白名单内返回观测。控制器维护实际故障及恢复状态，作为实验评价依据；不把故障答案或预写错误候选交给真实自主实验中的 Agent。

信息分为三类：现场工具观测、待验证候选解释、手册知识。现场观测描述本次采集对象及时间窗口内的事实；候选解释用于决定检查方向；PDF 检索结果只提供排查参考。手册描述某错误的常见原因，不能证明本次错误由该原因引起。工具返回内容与检索文本均作为不可信数据处理，不能扩大执行权限。

### 2.2 实际执行链路

诊断请求由 FastAPI 路由交给 AIOpsService，LangGraph 组织 planner、executor 和 replanner。planner 生成初步计划，executor 选择实际工具及参数并保存调用结果；replanner 根据证据和调查记忆决定下一项检查或结束。SSE 将过程送到前端，运行记录用于刷新后读取。

这里必须区分图节点与实际策略：create_replanner 在 autonomous_investigation 为真，且注入的是 DefaultReplanStrategy 或 DynamicClassificationStrategy 时，委托 InvestigationStrategy。不能仅凭注入的策略类名或旧文件注释，认定现场调查正在执行旧动态分类算法。其他路径与审批分支保留兼容，本研究不宣称全部请求都经过同一策略。

技术栈为 Python/FastAPI、LangGraph、MCP/Windows Probe、SQLite 与 Vue 3/Vite。检查目标由调查策略给出，工具参数仍由执行器选择并接受原有守卫；机制本身不授予额外权限。

### 2.3 现场证据与有限条件

现场证据进入索引时校验 Probe 来源、目标、hash 和时效。用于机制的记录还需经过当前观测选择及业务范围过滤。相同范围下被更新的引用、截断数据与不适用的工具口径不能直接被解释为可靠排除。引用核验确认 ID 与原文关系，不等于验证自由文本推理。

候选可携带一个必要的可核查预期，表示为 operation、object_name、field、expected。当前操作域包括 dependency_probe、services、ports、processes；字段域包括 tcp、http.status、state、listening、process_present，实际组合仍受解析和校验约束。例如某解释要求下游 TCP 不可达，检查结果却为可达，可以反驳这一有限预期；它不能因此证明另一段自由文本因果解释。

同范围适用观测的值不一致时，条件关系保持中性，不强行选一条作为反证。进程未观察到需满足相应覆盖规则，截断快照中没出现进程不能等同于进程不存在。没有条件、没有适用记录或权限不足时，也不能把未查明写成反驳。

### 2.4 知识辅助的实现范围

现有免费验收将三份项目运维 PDF 导入本地 BM25 知识库 15，共 6 页、8 个片段，并核对检索、页码及原文回溯。它支持知识辅助接线与来源追溯的工程说明，不支持宣称 RAG 提高了诊断准确率。四组实验固定知识内容、版本及检索条件，暂不另做知识效果研究。远程索引核验与本地知识条件审计分开记录。

## 第三章 有限假设保护与矛盾触发方法

### 3.1 候选状态与更新

当前主链路使用模型动态提出的解释，而不是固定七类假设的概率分布。每个候选保存稳定 ID、解释、必要预期、待执行的鉴别检查、创建步骤、状态、证据关联及已见观测标识；支持和反证计数是条件关系记录，不是经校准的根因概率。

模型继续讨论已有候选时引用其 ID。描述改写本身不提供自动语义合并保证；无显式 ID 时仅沿用实现允许的精确描述与条件匹配。引用不存在的 ID、对象或操作不一致等身份错误会阻止继续调度，保留证据及限制。同一 ID 保留原必要预期，不能通过改写预期抹掉反证。

观测去重标识由范围、diagnostic_fingerprint 和条件组成。重复采集同一诊断内容不会仅因重新分配 evidence ID 就重复增加支持或反证计数。计数可以解释更新过程，但不构成概率收敛或诊断正确性的证明。

### 3.2 有限假设保护

设当前已完成 executor 步骤数为 t，候选创建步骤为 b，步龄为 max(0, t-b)。保护期限 K 来自 INVESTIGATION_PROTECTION_STEPS，源码默认 2，允许 0 至 8；每场以保存的实际配置为准，默认值不代表所有运行的有效值。步龄严格小于 K 才满足期限条件；它不是墙钟时间，也不是重新描述候选后重置的机会。

保护针对本轮被模型遗漏的候选，以及模型提出 excluded 却因排除依据不足被回退的候选。只有开关开启、仍在期限内、没有可靠反证、状态允许且存在合法未完成的鉴别检查，才进入 protected。已可靠排除、不可用或 dropped 的候选不因此复活。候选仍被正常提出时也不必产生保护事件。

鉴别检查需要检查目标、实际工具名、待区分的问题和预期观测，且须通过工具能力、重复检查等校验。调度器优先选择符合条件的受保护候选进行检查。保护的目的只是保留一次有限核查机会，不保证该候选正确；保护错误方向可能增加检查代价，应在实验中如实记录。

到期后候选不会仅因旧保护身份无限保留；若继续被模型明确提出，则按普通候选处理。记录保护与到期事件用于解释状态，但事件出现不等于机制改变了实际工具执行。

### 3.3 可靠矛盾触发

在应用本轮模型候选改写前，系统先读取上轮领先候选的已保存必要预期。只有出现未被该候选消费过的新观测标识，且适用记录对有限预期形成明确反驳，才形成机制的反证触发机会。重复数据、模糊措辞和任意异常不直接算触发。

开关开启时，调度器从其他 active 或 protected 候选中选择没有被反驳、且具备合法鉴别检查的候选。当前实现采用候选遍历顺序中首个符合条件者，并未实现概率最优或信息增益最优选择。选中后将其检查写回计划，交由原执行器执行。

若原领先预期被反驳却没有合法替代检查，则记录 contradiction_blocked，保留证据并停止继续调查；最终仍经结论裁决生成故障层或未定位报告。阻塞不能计为成功改向。矛盾调度优先于保护调度；反证成立时保护不能强行忽略它。

机制关闭后，模型仍可根据证据自行调整计划。全关组是具备正常再规划能力的调查基线，不能故意限制其改向来制造机制收益。

### 3.4 一轮更新流程

1. 读取当轮证据、当前业务范围与模型提出的候选和检查。
2. 校验引用、候选身份、条件及检查合法性，保留原模型建议以便追溯。
3. 在改写候选前判断旧领先预期是否遇到新反证，随后更新候选关系及去重计数。
4. 按期限与证据处理遗漏和无依据排除，必要时保留受保护候选。
5. 先尝试矛盾调度；无相应触发时再尝试保护调度，否则沿用合法模型检查。
6. 有合法新检查则继续；无检查时按统一证据门槛报告故障层、范围内健康或未定位。

### 3.5 统一结论边界与人工建议

四组共用 decide_from_evidence。当前非健康自由文本 confirmed_cause 建议会被降级并保留为待核实推断，不能因日志包含报错或引用匹配就确认根因。可直接核验的有限故障线索支持 localized_fault，例如依赖连接失败、预期端口未监听或配置进程未观察到；它们不说明更深原因。无合法新检查且证据不足时报告 unlocated。

healthy_within_scope 要求正常现场证据、替代解释及允许对象的相关服务、依赖和预期端口等检查满足门槛，只描述本次核查范围。有限窗口或截断快照不支持全机、所有业务或长期健康结论。

人工处理建议依据当前有效故障层生成，包含对象、证据引用、前提、风险与处理后验证。建议明确尚未执行，由人先核对；系统不自动修复，也不把建议中的可能原因补成既定根因。

## 第四章 工程核验与自主实验方案

2026-10-26新增的版本固定、真实重置、受控失败和历史API输出材料见[工程验证与演示材料补充](工程验证与演示材料-20261026.md)。原有批次仍按本稿原日期解释，不把新观测或重放合并为自主效果样本。

### 4.1 研究问题和当前证据状态

拟回答：保护是否减少正确候选被过早丢弃；矛盾触发是否促成反证后的有效改查；两者的组合是否有收益或代价；错误结论、诚实未定位与检查成本如何变化。当前免费记录可以验证工程接线与裁决边界，尚不能回答自主模型的效果问题。旧策略效果数值不迁入本节。

| --- | --- | --- | --- |

上述两批没有相同完整观测，但这不证明试验独立；24 次重放与 12 场固定决策调查不能合并为 36 个自主实验。hash 一致只能说明材料未变，不能替代语义审核。

### 4.2 机制行为与代价的已有核验

机制行为评分关联原模型检查、候选 ID、反证、计划变化以及随后成功工具的对象参数。同一检查没有额外改向；产生事件却没有执行相应工具不算执行成功；缺上下文标 not_assessed，不能默认为通过。

12 场记录中，保护实际改查 2 次，矛盾实际改查 2 次，反证后阻塞 6 次。这些来自固定候选与固定决策，只证明调度和执行接线，不证明正确候选曾被自主模型过早丢弃。其余未触发或未额外改变的情况也需保留，不能只展示触发案例。

每场 5 次工具调用含 2 次准备与 3 次执行；仅后 3 次有计时。本批已记录耗时之和为每场 492.20—584.87ms，不是完整诊断耗时。各场相对对应 G00 的调用差均为 0，但固定 3 步停止条件、每条件一次且顺序未随机，不能估计机制的真实因果开销。本场模型费用缺记录时保持未知，不能填 0；免费核验没有新模型调用，不等于获得了免费自主模型实验。

### 4.3 待开展的自主四组实验协议

本节是待执行方案，不是已完成结果。按既有免费优先约定，当前不启动真实模型或新故障，费用提案暂缓。未来进入自主实验时，先用少量开发样本检查调用、记录和费用，再决定正式规模；预实验不混入保留样本。

控制器依次重置业务和日志、确认实际故障；独立随机安排四组运行，向 Agent 只给中性症状与允许对象；保存每轮模型提议、实际工具参数、原文与采集时间、候选状态和报告；结束后揭晓事实，机械核验和人工审核分开进行；最后核对恢复。每场独立线程、上下文和状态，前组答案与轨迹不进入后组知识检索。失败、超时、重试和缺件均保留。

覆盖正常、下游不可达和应用自身错误，并包含机制适用与不适用条件。机制适用性必须由实际轨迹核对，不能预写错误领先候选保证触发。保留未参与提示词或规则调参的样本；模型非确定性与本机测试业务的外部有效性限制需写明。

### 4.4 评分与结果表模板

故障定位正确性由预设现场事实与最终对象/故障层对应关系审核，不能用 conclusion_level 标签代替正确性。未完成计入已发起运行分母并单列，诚实未定位不计定位成功。引用支持与建议适用性分别审核；空工具轨迹、机械检查失败或未填人工意见的记录不能记为正确。

保护评估既记录候选是否保留并实际核查，也审核后续证据是否支持以及是否增加无效检查。矛盾评估区分触发机会、实际改查、原检查本已相同、无合法替代而阻塞及缺上下文。没有触发机会的运行单列，不静默删去；效果不能由事件数量推出。

### 4.5 当前局限

当前工程核验未验证自主收益；自由文本深层因果不能自动确认；有限条件只覆盖已实现操作与字段；候选选择顺序并非最优策略；固定决策记录的时间与费用不完整。真实人工语义审核、保留样本自主四组及完整费用记录仍未完成。当前材料不能支撑概率校准误差、生产泛化能力或系统保证诊断正确等结论。

# AIOps 故障诊断 Agent 答辩问题清单

这份清单按当前项目真实实现整理，不是标准答案。答辩时先讲事实、证据和限制，再讲设计意图；不能把尚未完成的自主实验说成已经验证。

## 一、选题与范围

1. **为什么做 AIOps 故障诊断 Agent？**
   - 入口错误通常不能直接说明根因，需要多次工具检查和证据比较。项目目标是定位可核验故障层、解释证据并给出人工处理建议。
2. **为什么不直接写规则？**
   - 规则适合固定故障，但本项目需要根据现场结果决定下一项检查；模型负责提出候选和检查计划，确定性代码负责工具权限、证据校验和结论边界。
3. **系统的研究范围是什么？**
   - Windows 本机专用测试业务，应用级故障，Agent 调查，人执行修复。多 Agent、自动修复、跨主机和 Pi runtime 迁移不属于当前必达范围。
4. **开题题目和现在的实现是否完全一致？**
   - 归档开题题目含“旁开式动态分类”，开题还写过概率、孵化复活和降级等较宽内容；当前实现和确认路线聚焦有限假设保护与可靠矛盾触发，差异已单列，正式题目以导师确认和学校要求为准。

## 二、从请求到报告

5. **用户提交请求后，代码怎么走？**
   - FastAPI 路由接收请求，AIOpsService 建立调查状态，LangGraph 运行 planner、executor、replanner；executor 调工具保存原始结果，replanner 更新候选和下一检查，最后生成报告并通过 SSE 和持久化记录返回前端。
6. **LangGraph 在这里解决什么？**
   - 它组织有状态的多轮节点执行和 checkpoint；不是自动保证诊断正确。状态中的计划、已执行步骤、原始证据和调查记忆决定下一轮输入。
7. **异步和 SSE 的作用是什么？**
   - 工具和模型调用可能等待 I/O，`await` 允许流程等待时不阻塞整个服务；SSE 把计划、步骤、报告和完成事件逐条推到页面。
8. **真正决定下一步的是哪个策略？**
   - 需要沿 `src/api/routers/aiops.py`、`src/agent/aiops/graph.py`、`src/agent/aiops/replanner.py` 追到实际注入的策略，再看 `strategies/investigation.py`；不能只看旧类名或页面标签。

## 三、两项核心机制

9. **假设保护解决什么问题？**
   - 候选早期缺少支持时，若没有可靠反证、仍有合法鉴别检查且未超过有限步龄，暂时保留一次核查机会；它不表示候选正确，也不无限复活。
10. **矛盾触发解决什么问题？**
    - 当领先候选的必要可核查预期被新的适用现场证据反驳时，优先选择其他合法候选的鉴别检查；没有合法替代时记录阻塞，不能把阻塞算作成功改向。
11. **为什么日志出现错误就不能确认根因？**
    - 日志是现场事实，但错误词可能是下游症状；当前裁决不能验证任意自由文本因果。必须区分观察到的故障层、未决解释和深层原因。
12. **什么情况下不触发机制？**
    - 候选没有条件、证据重复或不适用、检查不可执行、保护已到期，或模型本来就选择了相同检查，都不能虚构保护或改向收益。
13. **两项机制怎样独立？**
    - 四组使用同一调查实现，只切换假设保护和矛盾触发；模型、工具、知识、证据更新和结论门槛固定。全关组仍允许普通模型再规划，不能换成另一套策略制造差异。

## 四、证据、工具与知识

14. **现场证据和 PDF 知识有什么区别？**
    - Probe 返回本次目标、操作、采集时间和原文 hash 的现场观测；PDF/RAG 是排查参考，必须能回到页码和原文，不能证明本次故障。
15. **为什么要保留 evidence_id、采集时间和 hash？**
    - 让报告中的引用能回到同一条原始记录，识别旧窗口、重复读取和被修改的材料；hash 一致仍不等于因果判断正确。
16. **工具权限由谁控制？**
    - 工具目录、参数白名单、Probe 配置和服务级权限共同限制执行器；模型填写的 `next_tools` 是计划，不会凭空获得任意主机、文件或命令权限。
17. **为什么入口 503、下游 200 还要继续查？**
    - 入口表象不能区分下游、入口配置、健康检查或调度问题；应继续查入口日志、进程/端口和允许的内部状态。
18. **如果某类日志或事件不可用怎么办？**
    - 标记 unavailable 并保留限制，不用诊断服务自身状态代替目标事实，也不把缺失当成正常或故障。

## 五、实验与评价

19. **固定决策和自主实验有什么区别？**
    - 固定决策只能证明 Probe、MCP、状态和事件接线；自主实验要求模型在不知道控制器答案时自己选择检查。二者不能合并成自主样本。
20. **怎样判断定位正确？**
    - 用控制器保存的实际故障事实与最终对象/故障层对照，再由人工审核证据和因果边界；不能用 `conclusion_level`、引用字符匹配或事件数量代替正确性。
21. **为什么要保留未定位、错误和失败？**
    - 它们决定分母和真实边界。删除失败或只展示触发案例会夸大机制收益。
22. **如果四组实验没有提升怎么办？**
    - 报告没有提升、适用条件和额外检查代价；不更换样本或删失败直到结果好看。机制的价值也可能体现在解释性和诚实未定位，而非准确率提升。
23. **当前有哪些结果不能写进论文？**
    - 12场固定决策不能写成自主收益，24次历史重放不能写成24个独立故障，缺 usage 不能写费用为0，人工审核 pending 不能写诊断正确。

## 六、工程与答辩反问

24. **系统能自动修复吗？**
    - 不能。系统只给带对象、引用、前提、风险和处理后验证的人工建议，由人核对并执行。
25. **系统能证明任意根因吗？**
    - 不能。当前能报告有限条件支持的故障层或诚实未定位，深层自由文本因果仍需额外证据和人工审核。
26. **如何复现当前版本？**
    - 页面和服务读取当前工作树文件，Git 分支名不会自动选择代码；免费材料包通过源码和产物 hash 固定。运行时应记录工作树、配置、依赖、场景和原始证据。
27. **为什么主线以 main 为主？**
    - `main` 是集成和演示主线，独立功能可在 `codex/` 分支开发，验收后再合并；页面不会按分支名自动呈现，而是读取启动目录的工作树。
28. **项目目前最大的限制是什么？**
    - 真实自主模型四组实验和人工语义审核尚未完成；当前工程验证证明了接线、来源和边界，不能替代自主效果证据。

## 每次代码改动的讲解流程

1. 先指出用户请求进入的 API、实际调用者和状态字段。
2. 说明当前缺口、预期行为和最小修改位置。
3. 修改代码及必要测试，保持模型、工具和数据范围不扩大。
4. 先跑直接相关的免费测试，再根据接口或前端影响扩大验证。
5. 阅读真实输出，区分通过、失败、未运行和既有失败。
6. 用一条具体调用链复述“证据如何改变下一步”，再更新论文材料和路线记录。

下一步从前端调查卡片与后端 `investigation_summary` 的对应关系开始，核对页面是否同时展示本轮证据、当前候选和下一检查理由；确认缺口后再做最小代码改动。

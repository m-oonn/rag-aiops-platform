## 1.1 研究背景及意义

### 1.1.1 研究背景

微服务化之后，一次故障往往不再只是"某个服务挂了"：一处出问题会引发一连串跨服务报错，真正成因被埋在连锁现象之下；工程师要在指标、日志、调用链之间反复翻找，靠个人经验而非可复用的流程——由此带出三个老毛病：**响应慢**、**质量不稳定**、**经验难沉淀**。综述已归纳出该方向的两个前提性局限：依赖预设的服务拓扑或指标集、难以处理未出现过的故障组合【文献 1】【文献 2】。近两年大语言模型在推理与工具调用上能力增强，给出一条新路径：由**一个**诊断智能体自行规划排查步骤、调用接口采集证据、再依观测结果调整下一步（**规划—执行—再规划**），其学术原型是 ReAct【文献 17】与 Plan-and-Solve【文献 18】。本文研究的正是这条流程的失效情形——**隐藏故障**：症状复杂、跨组件，看似指向复杂成因，真实根因却往往只是单点问题（CPU 饱和、内存溢出、连接池耗尽、网络抖动）。

### 1.1.2 研究意义

本文拟解决的问题是：**在症状复杂、证据噪声大、工具可能部分缺失时，让大语言模型诊断智能体判得准、说得清、不瞎猜、坏不掉。** 直接把模型接进诊断流程会暴露三个**结构性**缺陷：（i）**结论不可审计**——只给一个根因字符串，无法回答"凭什么这样判定"，RCAgent 等代表性工作同样止于最终答案、中间推理未作可审计设计【文献 27】；（ii）**置信度不可靠**——证据不足时仍用确定语气，且与有证据支撑的结论**格式完全一致**（实测：停日志服务后 8 场景中 3 例虚报确定）【实测】；模型置信度失准是既有课题【文献 30】；（iii）**工程链路脆弱**——工具为独立服务，任一不可用即取不到证据甚至链路中断（实测：修复前停一个服务即 8 个工具全废）【实测】；这属自愈系统的经典问题【文献 38】。三者共同后果是**结论不可追责、不可信任，环境稍一波动就干脆不出结论**。据此本文的核心主张是——**不做"又一个能出结论的诊断系统"，而是把故障诊断从一次黑箱文本生成，改造成一个可审计的信念更新过程**；该系统须兑现三条承诺：**可收敛**（必须给答案）、**可审计**（必须说清结论来源）、**诚实**（证据不足必须如实说明）。

## 1.2 研究现状分析

> **交付节点：9 月 19 日交付初版；后续补充；10 月 10 日交付最终版。**

### 1.2.1 整体分析

**（1）应用广泛性与研究价值。** 智能运维（AIOps）覆盖异常检测、告警收敛、根因定位、容量预测、故障自愈等环节，其中**根因定位**是与本文最接近、也最难的一环：需求端，凡有线上业务的企业均面临"告警多、排障慢"；方法端，它需要把指标、日志、调用链三类异构证据关联起来推断，天然是"证据不完整、结论靠推断"的问题。近年该方向已形成多篇系统性综述：面向微服务云应用的方法学综述梳理出指标/日志/追踪三条主线【文献 1】；面向微服务根因定位的专门综述进一步按"单模态 / 多模态 / 智能定位"划分方法族并指出评估基准缺失【文献 3】；面向 LLM 时代的 AIOps 综述则把"LLM 如何进入检测、定位、修复各环节"作为新的组织维度【文献 2】。日志分析方向另有专门综述【文献 4】【文献 10】，AIOps 失效管理已有方法学总结【文献 5】，LLM 智能体本身亦已形成系统性综述【文献 24】【文献 25】。这些综述共同指出的一个前提性局限是：**依赖预先定义的服务拓扑或指标集**，以及**难以处理训练/规则中未出现过的故障组合**——这两个前提在隐藏故障上恰好都不成立（症状位置与根因位置不一致，组合方式事先不可枚举）。

**（2）代表性研究及其方法与效果。** 按"检测 → 规划 → 根因分析"三组列出与本课题最直接相关的代表性工作（会议/期刊均标注级别）。

| 代表性研究 | 采用的方法 | 取得的效果 |
|---|---|---|
| 研究 1：DeepLog【文献 6】（ACM CCS 2017，**CCF-A 会议**） | 用 LSTM 对日志事件序列建模，偏离正常模式即判异常 | 在 HDFS、BGL 等公开日志集上优于同期规则/统计基线，可检出"未见过但模式相近"的异常；但只回答"**有没有异常**" |
| 研究 2：LogAnomaly【文献 7】（IJCAI 2019，**CCF-A 会议**） | 在 DeepLog 基础上引入日志模板语义向量与计数，做序列/数量两类异常的无监督检测 | 无需人工标注即可适应新模板；针对日志不稳定（模板演化）场景的改进工作见 LogRobust【文献 8】；但均**止于检测层面**，不给出根因 |
| 研究 3：微服务根因定位方法族（MicroRCA【文献 11】NOMS 2020 / MicroRank【文献 12】WWW 2021 / Eadro【文献 13】ICSE 2023 / Nezha【文献 14】ESEC-FSE 2023 / 多模态融合方法 HeMiRCA【文献 15】ACM TOSEM 2024 / 基于追踪的多维定位方法【文献 16】ICSE 2024） | 利用调用链与资源指标的相关性、服务依赖图上的异常传播、或日志+指标多模态融合来定位故障服务 | 在依赖关系明确的场景下可定位到服务乃至实例粒度，Nezha 等已能给出多模态可解释线索；**依赖预设拓扑与稳定指标采集**，当"症状集中处"与"根因发生处"分离时精度下降 |
| 研究 4：ReAct【文献 17】（ICLR 2023，**CCF-A 会议**） | 把"推理一步"与"行动一步"交替插入同一条轨迹，边思考边调工具 | 在 HotpotQA/Fever 上接入 Wikipedia API 缓解了幻觉与错误传播；ALFWorld/WebShop 上仅用 1~2 个示例超过模仿学习与强化学习基线（报告绝对成功率 +34%、+10%）；但仍是**单条思路线性推进** |
| 研究 5：Plan-and-Solve【文献 18】（ACL 2023，**CCF-A 会议**） | 先出计划把任务拆成子任务，再按计划执行 | 在 10 个数据集上一致优于 Zero-shot-CoT；但**计划一旦生成即按序执行**，缺少被新证据推翻后另开分支的机制 |
| 研究 6：该范式家族的扩展——Reflexion【文献 19】、Tree-of-Thoughts【文献 20】（均 NeurIPS 2023，**CCF-A 会议**）、Toolformer【文献 21】、Self-Refine【文献 22】（NeurIPS 2023）、CoT【文献 23】（NeurIPS 2022） | Reflexion 让模型对自身失败做语言化反思后重试；ToT 把推理展开为可回溯的搜索树；Toolformer 让模型自学工具调用；Self-Refine 用自反馈迭代改进；CoT 用中间推理步骤提升复杂推理 | 各自在推理、决策与工具使用任务上取得提升；但 Reflexion 的反思以"整段任务失败"为单位、**对多个并存假设无细粒度管理**，ToT 的搜索价值函数**不承载"证据—假设"的概率语义**，且**无一致性与收敛保证** |
| 研究 7：LLM 云故障根因分析（RCAgent【文献 27】CIKM 2024 / RCACopilot【文献 26】**EuroSys 2024** / Xpert【文献 28】ICSE 2024 / Nissist【文献 29】ECAI 2024） | 用带工具的自主智能体或检索增强流程做云环境根因分析，引入领域知识库、历史工单辅助 | 在真实云场景中验证了"LLM 做根因分析"的可行性，RCACopilot 已在生产事故上评测；但均以**最终答案**形式输出，**中间推理的可审计性与结论置信度未作专门设计** |

**（3）小结：上述研究仍存在的具体问题与三个难点瓶颈。**

上述研究共同证明了两件事：AIOps 的异常检测与根因定位已有成熟方法积累（研究 1~3）；大语言模型智能体能够完成多步工具调用与推理，且已被用于云故障根因分析（研究 4~7）。需指出的是，针对日志异常检测方法的独立评估研究表明，此类方法在跨数据集迁移时性能显著下降【文献 9】——这与上述"难以处理未出现过的故障组合"的判断互相印证。但二者结合、用于隐藏故障时，仍存在一个共同问题——**诊断过程缺乏对候选原因的显式管理，也缺乏对结论可信度的约束**。该问题可具体拆解为三个难点瓶颈：

- **难点 1（假设管理与证据推理）**：现有流程均为"线性推进"（研究 4）或"计划即承诺"（研究 5），既不保护"早期正确但证据尚不足"的简单假设，也不在证据矛盾时另开分支；即便是具备回溯能力的 ToT【文献 20】，其搜索节点也不携带"该证据对哪个候选根因构成多少支持/反对"的概率语义。可观测的具体错误有两类：**过早放弃简单假设**（面对复杂症状采用"复杂症状 ⇒ 复杂根因"的先验，把起初正确的简单假设过早淘汰）；**被复杂症状带偏**（大量级联 ERROR 日志主导证据权重，把诊断引向调用链末端的次级故障，而链路首端的真实根因因日志稀少被淹没）。
- **难点 2（不确定性表达与诚实性）**：证据不足时仍输出确定语气的结论，且结论格式无法区分"有证据支撑"与"来自先验猜测"。现象级证据：停用日志服务后 8 个场景中 3 例为"虚报确定"【实测】。模型置信度失准（ECE 偏高）是神经网络的普遍现象【文献 30】，LLM 领域也已形成"在词上表达不确定性"【文献 31】、"语义熵"【文献 33】、"一致性自检"【文献 34】、"应否弃答"【文献 35】四条应对路线——但它们均**不面向"多候选根因 + 分批到达证据"的诊断结构**。任何只比对 Top-1 结论字符串的评估都会把这类猜测计为正确，从而**掩盖**缺陷。
- **难点 3（链路鲁棒性与结论可审计性）**：诊断依赖外部服务，单点不可用即导致证据缺失甚至链路中断（现象：停一个服务即 8 个工具全部不可用【实测】）；同时系统只输出结论、不给推理轨迹，结论无法复核、责任无法界定。可解释 AI 领域已给出通用解释框架【文献 37】，但"如何在**降级条件**下仍保证结论可信并标注降级来源"缺少针对性方法。

**（4）三者的依赖关系**：三个难点并非并列，而是递进依赖，这直接决定方法选型，详见 §1.2.5。

### 1.2.2 难点 1 分析（假设管理与证据推理）

**问题界定**：候选根因不止一个，证据分批到达、强度不均、且与根因不在一处。核心问题是：在"证据的时间顺序与强度分布会系统性误导判断"的条件下，如何收敛到真实根因。

| 方法 | 做法 | 效果 |
|---|---|---|
| **1A** 规则/阈值脚本决策【文献 36】 | 把专家经验写成 if-else 或决策树（如"CPU>90% 判 CPU 饱和，否则查内存"）；决策论排障框架进一步给出"按期望代价排序检测动作"的形式化 | 对已预设的故障模式稳定、可解释、开销极低；但**先验须人工给定，不做证据驱动的信念修正** |
| **1B** 显式假设空间 + 信念更新 + 假设保护与分支（本文方案） | 为每个候选根因维护概率，用新证据更新；对早期假设加保护期，矛盾时另开分支，必要时孵化或复活假设 | 可同时表达多个候选原因并排序，具备处理隐藏故障的机制基础 |
| **1C** 思考—行动交替的自由循环（ReAct 式）【文献 17】；树搜索扩展【文献 20】 | 不设显式假设结构，每一步由模型自行决定下一步查什么；ToT 以搜索树承载多条推理路径 | 灵活性高、轨迹可读；ToT 具备回溯能力；但**候选原因之间无概率比较**，回溯依据是启发式价值而非证据 |

**小结**：可解决难点 1 的方法有 ——
- **1A 规则/阈值脚本决策**【文献 36】：稳定但僵化，规则一经写死即不随新证据调整，无法处理未预设的故障组合；
- **1B 假设空间 + 信念更新 + 假设保护 + 矛盾触发旁开 + 孵化/复活**：显式管理多个候选原因，具备收敛与可解释基础；
- **1C 纯自由循环（ReAct / ToT 式）**【文献 17】【文献 20】：灵活但缺乏收敛保证，且不区分各候选原因的可能性大小。

### 1.2.3 难点 2 分析（不确定性表达与诚实性）

**问题界定**：当关键证据源缺失或证据强度不足时，系统应如实说明"证据不足"，而非给出貌似确定的结论。核心问题是：如何**量化"证据是否充分"**，并让可信程度**可被程序消费、可被断言**。

| 方法 | 做法 | 效果 |
|---|---|---|
| **2A** 证据充分性门控 + 结论状态标注 + 双轨报告（本文方案） | 生成结论前先检查关键证据是否到位，按"充分/降级/缺失"分级；结论状态同时以人读文本与机读结构化字段输出 | 信息不足时不伪装确定；结论可被下游程序自动断言 |
| **2B** 置信度阈值硬过滤 / 后验校准【文献 30】 | 设单一概率阈值，低于阈值即拒绝输出或返回"无法判断"；或用后验校准修正置信度 | 实现简单，能挡住部分明显不可靠的结论；但只给"能/不能"、不给候选，且阈值可靠性同样依赖证据判断 |
| **2C** 不确定性量化与一致性投票【文献 31】【文献 32】【文献 33】【文献 34】【文献 35】 | 在词上表达不确定性；模型对自身知识边界做事前自评；语义熵度量语义等价集合的不确定性；多次采样做一致性自检；在无法回答时弃答 | 从概率与语义两个层面改善置信度的可靠性，MMLU 等基准上已验证其有效性；但成本成倍增加，且**无法区分"一致地错"与"正确地一致"，对"证据源整体不可用"无能为力** |

**小结**：可解决难点 2 的方法有 ——
- **2A 证据充分性门控 + 结论状态标注 + 双轨（人读/机读）报告**：不虚报且可程序断言；
- **2B 置信度阈值硬过滤 / 后验校准**【文献 30】：简单，但信息量低（只给"能/不能"，不给候选），且阈值可靠性同样依赖证据判断；对"证据本身缺失"无改善；
- **2C 采样一致性投票 / 语义熵**【文献 33】【文献 34】：降低随机性，但成本成倍增加，且无法区分"一致地错"与"正确地一致"，对"证据源整体不可用"这一类缺失无能为力。

### 1.2.4 难点 3 分析（链路鲁棒性与结论可审计性）

**问题界定**：诊断依赖的外部服务随时可能故障或超时；同时工程师需要知道"结论是怎么来的"。核心问题是：如何在**工具降级**条件下仍**可用且可信**，并输出**可复核的决策依据**。

| 方法 | 做法 | 效果 |
|---|---|---|
| **3A** 重试 + 超时 + 熔断【文献 38】 | 对失败的工具调用做有限重试，超时即中断 | 缓解瞬时故障，实现成本低；但持续不可用时仍然失败，且不提供替代证据来源 |
| **3B** 全量降级为纯语言模型问答 | 工具全部不可用时，让模型凭自身知识作答 | 保证系统"总能说话"；但结论无证据支撑、易幻觉，反而放大难点 2 |
| **3C** 按服务粒度容错 + 本地证据降级源 + 降级来源可审计（本文方案） | 工具按 server 逐个独立加载；关键证据保留本地副本，在线服务不可达时改读副本并显式标注降级来源 | 单点故障不再导致整体失效；降级路径下仍能产出结论且来源可追溯 |

**小结**：可解决难点 3 的方法有 ——
- **3A 重试 + 超时 + 熔断**【文献 38】：只治瞬时故障，工具服务持续不可用时仍然失败，且不提供替代证据来源；
- **3B 全量降级为纯问答**：保证可用但结论无证据支撑、易幻觉，反而放大难点 2；
- **3C 按 server 粒度容错加载 + 本地日志降级源 + 降级来源可审计**：单点故障不致全盘失效，降级路径下结论仍可信、来源可追溯。

### 1.2.5 分析总结

**（1）难点之间的依赖关系及其原因。** 三个难点是**递进依赖**而非并列，这决定了解决顺序必须是"一 → 二 → 三"。

- **难点 2 依赖难点 1**。要判断"证据是否充分"，前提是先存在一个**"证据 → 候选假设"的映射结构**以及各候选假设的概率分布；只有先知道"哪些证据在支持或反对哪个根因"，才谈得上"针对某个根因的证据够不够"。若没有难点 1 提供的假设空间，"证据充分性"这一概念**无从度量**，难点 2 的门控将失去判定依据。**故必须先解决难点 1。**
- **难点 3 依赖难点 1 与难点 2**。一方面，可审计性的核心材料——信念轨迹、证据与假设的对应关系、决策记录——**直接来自难点 1 的假设空间**；另一方面，鲁棒性设计中最关键的一环是"工具降级时结论仍要诚实"：若没有难点 2 的诚实性门控，系统在证据缺失时只会产出**语气更确定的错误结论**，即"降级"反而放大不可信。**故难点 3 必须建立在难点 1、难点 2 之上。**
- **顺序的必然性**：若颠倒顺序（例如先做鲁棒性、后做诚实性），将得到"在证据缺失时稳定地输出错误结论"的负面结果。

**（2）拟采用的方法组合与关键机制参数。** 据此，本文拟采用 **1B、2A、3C** 依次解决难点 1、2、3。下表参数**全部取自本项目源码**，逐条给出文件与行号（完整对照见 **附录 A**）。

**（4）核心抽象。** 上述机制合起来构成一个可命名的概念——**旁开式动态分类**（sidebar dynamic classification）：诊断不做单线推进，而是把候选根因维护成一个带概率的**假设空间**，证据到来时更新概率；当领先假设被矛盾证据否定、且诊断步数尚少时，不继续线性推进，而是**旁开**出一条新的排查支线。它不是一次端到端的文本生成，而是一套**可审计的信念更新过程**。其与"决策论排障"【文献 36】共享"用证据更新诊断信念"的思想，区别在于：经典框架假设**完整的故障-症状概率表可预先给定**，本文面向的是**候选假设与证据关系都需在线判定（由 LLM 裁判给出）**的场景。

**（5）载体与贡献的区分。**

| 层次 | 内容 | 地位 |
|---|---|---|
| 知识底座 | 检索增强生成（RAG）知识库（文档解析、混合检索、重排序、评测） | **载体**：作为诊断流程可调用的**工具**，不作贡献主张 |
| 诊断平台 | 三阶段诊断流程（规划 → 执行 → 再规划）与工具接入协议 | **承载平台**：机制运行的骨架（学术原型见【文献 17】【文献 18】） |
| 诊断机制 | 假设空间、信念更新、假设保护、矛盾触发旁开、孵化/复活、证据裁判、诚实性门控 | **← 本文贡献所在** |

**（6）与现有工作的差异。** 以 RCAgent【文献 27】、RCACopilot【文献 26】为代表的现有工作把语言模型当作"输入现象 → 输出结论"的黑箱（RCACopilot 虽引入历史工单检索，仍未显式维护候选根因的概率分布）；本文的差异**不在于接入更多工具或更大的系统**，而在于把诊断过程**显式建模为可审计的假设管理与信念更新过程**，并把"不确定性"与"降级来源"纳入结构化输出。这一差异可直接映射到三组已有研究线：相对 ToT 等搜索式推理【文献 20】，本文的搜索节点携带"证据—假设"概率语义；相对不确定性量化研究【文献 30】【文献 33】【文献 34】，本文把"充分性"定义为**针对特定假设的证据覆盖率**而非答案的整体置信度；相对可解释 AI【文献 37】，本文的解释对象是**在线决策过程**而非模型内部归因。

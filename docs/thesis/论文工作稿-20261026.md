## 摘要（暂行）

应用故障调查需要在信息不完整时逐步检查接口、依赖和日志。过早放弃候选解释或在遇到反证后继续沿原方向检查，可能影响调查。本文面向 Windows 本机专用测试业务，实现基于大语言模型与工具调用的 AIOps 故障诊断系统，研究有限假设保护与可靠矛盾触发。系统以 FastAPI 接收请求，利用 LangGraph 组织计划、执行与再规划，通过 MCP 和 Probe 获取观测。保护机制在有限执行步龄内为缺少排除依据且有合法检查的候选保留核查机会；矛盾机制依据新观测对必要预期的反驳调整检查，无合法替代时记录阻塞。两者共享权限和结论门槛，PDF 仅提供知识参考，修复由人操作。当前工程核验覆盖真实业务重置、相同 503 下的不同事实、旧日志拒绝、受控失败及历史输入的 API、SSE 和刷新一致性，并保存源码及材料散列。这些固定决策与历史核验不能证明自主效果。后续采用同一实现的四组开关实验，分别审核定位、错误、未定位、机制行为与成本。

关键词：AIOps；故障诊断；工具调用；假设保护；矛盾触发；证据追溯

## 第一章 绪论

### 1.1 研究背景与具体问题

一个接口返回错误，既可能由下游不可达引起，也可能来自入口自身的配置或应用异常。仅凭入口状态无法区分这些情况，调查者需要选择后续检查，并将新观测与已有解释比较。本项目关注的任务是在允许的业务范围内，逐步检查真实运行的测试业务，定位证据支持的故障对象或故障层，并明确仍未查清的问题。

大语言模型能够根据症状提出候选原因并选择工具，但模型提出的解释仍须接受现场核验。缺少早期支持不等于候选错误；日志包含某个错误词也不等于任意因果解释成立。若系统只保存最终答案，难以解释候选何时被舍弃、某次新证据为何改变计划，也难以区分合理调查与偶然猜对。

因此，本文将两个可检验的问题作为研究切口。第一，当候选所需的关键检查尚未执行时，能否以有限代价避免过早放弃？第二，当领先解释的必要预期被可靠新观测反驳时，能否使下一检查转向合法替代解释？这两个问题允许存在负面结果：保护错误方向可能增加工具调用，普通再规划也可能已经完成改向，机制不一定产生额外收益。

### 1.2 相关工作与本文定位

日志分析和智能运维研究涵盖数据处理、异常检测、故障预测与故障诊断。贾统等的综述从日志处理与特征提取、异常检测、故障预测、根因诊断四个方面组织相关技术[1]。包航宇等通过行业问卷与标准梳理讨论智能运维实践，并提出能力建设标准框架[2]。这些工作提供任务与工程背景；本项目没有实现一套新的日志异常检测模型，也不能用单个错误关键词命中替代故障因果核验。

在推理与行动结合方面，ReAct将推理轨迹与任务动作交替组织，使模型能够获取外部信息、更新行动计划并处理异常[3]。原文覆盖问答、事实核验以及ALFWorld和WebShop交互任务。因此，不能将ReAct概括为只能沿固定方向线性执行或无法改向。Plan-and-Solve通过先分解任务再依次求解的提示缓解多步推理中的遗漏步骤问题，并在推理数据集上评价[4]；它可以说明任务分解思路，但并不直接构成本项目工具反馈、持久状态与再规划运行时的实现依据。

在运维Agent方面，RCAgent研究工具增强的自主云根因分析，包含观测快照键、上下文管理与行动轨迹自一致性等设计[5]。所读预印本第4.2.1节介绍了工业Flink作业数据的筛选和SRE审核；该任务的数据、工具和根因答案定义与本项目的Windows专用测试业务不同。康俊驰等从信息获取、根因定位和效果评估三个流程梳理LLM智能体根因分析研究[6]。本文据此比较调查对象、观测来源和评价口径，不直接沿用其分数，也不因自己的系统保存了证据就声称首次实现可审计诊断。

在证据不足时，系统应允许保留未定位结果。Wen等从查询、模型和人类价值三个视角梳理LLM拒答方法、基准与评价[7]，可作为不强制回答的相关研究背景；本文的有限条件门槛并非复现该综述中的全部拒答方法。知识检索方面，BM25原理资料讨论词项权重与文档相关性排序[8]，本项目以其辅助检索排查手册。检索分数和手册描述都不能解释为本次根因成立的概率。

本文的具体研究对象是同一调查链路中的有限假设保护与可靠矛盾触发：记录候选的必要预期和已执行步龄，在存在合法检查时保留有限核查机会，在可靠反证出现时调整下一检查。是否比普通再规划产生额外收益，仍需同一实现的四组开关实验验证。Pi的事件与上下文源码、LangGraph及MCP官方文档属于工程设计依据，另列版本来源，不作为这两项机制有效性的证明。书目核对层次、原文位置及未完成项见[文献与开题范围核对](文献与开题范围核对-20261027.md)。

### 1.3 研究目标与实现范围

本研究的系统目标是完成“中性症状输入—自主选择检查—现场证据更新—下一检查或报告”的调查闭环。结论应区分可核验故障层、范围内健康和未定位；没有深层因果验证能力时不确认自由文本根因。研究目标是在同一实现与同一证据门槛下，检验有限保护与矛盾调度的行为及代价。

实现范围限定于自己的 Windows 电脑及独立专用测试业务，覆盖正常、下游不可达与应用自身错误等应用级情况。真实故障答案由控制器保管，Agent 只接收症状与允许对象。PDF/RAG 用于排查知识及来源追溯，实验保持知识条件一致。修复由人核对并执行。多 Agent、跨主机部署、自动修复、通用崩溃恢复及 Pi runtime 迁移均不作为本研究的必达目标。

### 1.4 研究内容与验证路线

研究内容包括：定义带稳定身份、必要预期和鉴别检查的候选状态；实现按执行步龄约束的假设保护；实现基于有限条件反证的替代检查调度；将两项机制接入现有调查循环，并保留原有参数守卫和共享裁决；建立来源可追溯的记录与四组评测入口。系统集成和记录基础设施服务于机制验证，不单独宣称为算法贡献。

验证分为工程核验与自主效果实验。工程核验使用免费离线测试、真实 Probe 采集配合固定决策，以及历史原文重放，检验接线、边界与持久化。自主效果实验则需要真实模型在隐藏故障答案的条件下选择工具，再进行独立的事实与语义审核。两种证据回答的问题不同，不能用工程通过数填补自主效果结果。

## 第二章 任务定义与系统基础

### 2.1 调查任务与信息边界

用户提交症状、允许调查的业务对象和配置范围。Agent 根据已有信息提出候选解释与检查，工具在原有权限和参数白名单内返回观测。控制器维护实际故障及恢复状态，作为实验评价依据；不把故障答案或预写错误候选交给真实自主实验中的 Agent。

信息分为三类：现场工具观测、待验证候选解释、手册知识。现场观测描述本次采集对象及时间窗口内的事实；候选解释用于决定检查方向；PDF 检索结果只提供排查参考。手册描述某错误的常见原因，不能证明本次错误由该原因引起。工具返回内容与检索文本均作为不可信数据处理，不能扩大执行权限。

### 2.2 实际执行链路

诊断请求由 FastAPI 路由交给 AIOpsService，LangGraph 组织 planner、executor 和 replanner。planner 生成初步计划，executor 选择实际工具及参数并保存调用结果；replanner 根据证据和调查记忆决定下一项检查或结束。SSE 将过程送到前端，运行记录用于刷新后读取。

这里必须区分图节点与实际策略：create_replanner 在 autonomous_investigation 为真，且注入的是 DefaultReplanStrategy 或 DynamicClassificationStrategy 时，委托 InvestigationStrategy。不能仅凭注入的策略类名或旧文件注释，认定现场调查正在执行旧动态分类算法。其他路径与审批分支保留兼容，本研究不宣称全部请求都经过同一策略。

技术栈为 Python/FastAPI、LangGraph、MCP/Windows Probe、SQLite 与 Vue 3/Vite。 本轮本机安装版本为LangGraph 1.0.7、langgraph-checkpoint 4.3.0、MCP Python SDK 1.26.0；官方在线文档按2026-10-27读取，仅引用图状态、checkpoint与协议初始化等概念，不将现行网页全部API视作已安装版本能力。SDK支持协议2025-11-25等版本，但本轮未启动连接测量实际协商版本。检查目标由调查策略给出，工具参数仍由执行器选择并接受原有守卫；机制本身不授予额外权限。

### 2.3 现场证据与有限条件

现场证据进入索引时校验 Probe 来源、目标、hash 和时效。用于机制的记录还需经过当前观测选择及业务范围过滤。相同范围下被更新的引用、截断数据与不适用的工具口径不能直接被解释为可靠排除。引用核验确认 ID 与原文关系，不等于验证自由文本推理。

候选可携带一个必要的可核查预期，表示为 operation、object_name、field、expected。当前操作域包括 dependency_probe、services、ports、processes；字段域包括 tcp、http.status、state、listening、process_present，实际组合仍受解析和校验约束。例如某解释要求下游 TCP 不可达，检查结果却为可达，可以反驳这一有限预期；它不能因此证明另一段自由文本因果解释。

同范围适用观测的值不一致时，条件关系保持中性，不强行选一条作为反证。进程未观察到需满足相应覆盖规则，截断快照中没出现进程不能等同于进程不存在。没有条件、没有适用记录或权限不足时，也不能把未查明写成反驳。

### 2.4 知识辅助的实现范围

现有免费验收将三份项目运维 PDF 导入本地 BM25 知识库 15，共 6 页、8 个片段，并核对检索、页码及原文回溯。它支持知识辅助接线与来源追溯的工程说明，不支持宣称 RAG 提高了诊断准确率。四组实验固定知识内容、版本及检索条件，暂不另做知识效果研究。远程索引核验与本地知识条件审计分开记录。 本地实现调用rank-bm25 0.2.2的BM25Okapi，并对检索结果作得分归一化；归一化值不代表因果置信度[8]。PDF解析实际使用PyMuPDF，不能因为环境安装了其他PDF库就将其写为本链路的解析实现。

## 第三章 有限假设保护与矛盾触发方法

### 3.1 候选状态与更新

当前主链路使用模型动态提出的解释，而不是固定七类假设的概率分布。每个候选保存稳定 ID、解释、必要预期、待执行的鉴别检查、创建步骤、状态、证据关联及已见观测标识；支持和反证计数是条件关系记录，不是经校准的根因概率。

模型继续讨论已有候选时引用其 ID。描述改写本身不提供自动语义合并保证；无显式 ID 时仅沿用实现允许的精确描述与条件匹配。引用不存在的 ID、对象或操作不一致等身份错误会阻止继续调度，保留证据及限制。同一 ID 保留原必要预期，不能通过改写预期抹掉反证。

观测去重标识由范围、diagnostic_fingerprint 和条件组成。重复采集同一诊断内容不会仅因重新分配 evidence ID 就重复增加支持或反证计数。计数可以解释更新过程，但不构成概率收敛或诊断正确性的证明。

### 3.2 有限假设保护

设当前已完成 executor 步骤数为 t，候选创建步骤为 b，步龄为 max(0, t-b)。保护期限 K 来自 INVESTIGATION_PROTECTION_STEPS，源码默认 2，允许 0 至 8；每场以保存的实际配置为准，默认值不代表所有运行的有效值。步龄严格小于 K 才满足期限条件；它不是墙钟时间，也不是重新描述候选后重置的机会。

保护针对本轮被模型遗漏的候选，以及模型提出 excluded 却因排除依据不足被回退的候选。只有开关开启、仍在期限内、没有可靠反证、状态允许且存在合法未完成的鉴别检查，才进入 protected。已可靠排除、不可用或 dropped 的候选不因此复活。候选仍被正常提出时也不必产生保护事件。

鉴别检查需要检查目标、实际工具名、待区分的问题和预期观测，且须通过工具能力、重复检查等校验。调度器优先选择符合条件的受保护候选进行检查。保护的目的只是保留一次有限核查机会，不保证该候选正确；保护错误方向可能增加检查代价，应在实验中如实记录。

到期后候选不会仅因旧保护身份无限保留；若继续被模型明确提出，则按普通候选处理。记录保护与到期事件用于解释状态，但事件出现不等于机制改变了实际工具执行。

### 3.3 可靠矛盾触发

在应用本轮模型候选改写前，系统先读取上轮领先候选的已保存必要预期。只有出现未被该候选消费过的新观测标识，且适用记录对有限预期形成明确反驳，才形成机制的反证触发机会。重复数据、模糊措辞和任意异常不直接算触发。

开关开启时，调度器从其他 active 或 protected 候选中选择没有被反驳、且具备合法鉴别检查的候选。当前实现采用候选遍历顺序中首个符合条件者，并未实现概率最优或信息增益最优选择。选中后将其检查写回计划，交由原执行器执行。

若原领先预期被反驳却没有合法替代检查，则记录 contradiction_blocked，保留证据并停止继续调查；最终仍经结论裁决生成故障层或未定位报告。阻塞不能计为成功改向。矛盾调度优先于保护调度；反证成立时保护不能强行忽略它。

机制关闭后，模型仍可根据证据自行调整计划。全关组是具备正常再规划能力的调查基线，不能故意限制其改向来制造机制收益。

### 3.4 一轮更新流程

1. 读取当轮证据、当前业务范围与模型提出的候选和检查。
2. 校验引用、候选身份、条件及检查合法性，保留原模型建议以便追溯。
3. 在改写候选前判断旧领先预期是否遇到新反证，随后更新候选关系及去重计数。
4. 按期限与证据处理遗漏和无依据排除，必要时保留受保护候选。
5. 先尝试矛盾调度；无相应触发时再尝试保护调度，否则沿用合法模型检查。
6. 有合法新检查则继续；无检查时按统一证据门槛报告故障层、范围内健康或未定位。

### 3.5 统一结论边界与人工建议

四组共用 decide_from_evidence。当前非健康自由文本 confirmed_cause 建议会被降级并保留为待核实推断，不能因日志包含报错或引用匹配就确认根因。可直接核验的有限故障线索支持 localized_fault，例如依赖连接失败、预期端口未监听或配置进程未观察到；它们不说明更深原因。无合法新检查且证据不足时报告 unlocated。

healthy_within_scope 要求正常现场证据、替代解释及允许对象的相关服务、依赖和预期端口等检查满足门槛，只描述本次核查范围。有限窗口或截断快照不支持全机、所有业务或长期健康结论。

人工处理建议依据当前有效故障层生成，包含对象、证据引用、前提、风险与处理后验证。建议明确尚未执行，由人先核对；系统不自动修复，也不把建议中的可能原因补成既定根因。

## 第五章 讨论

### 5.1 实现效果与证据强度

目前的实现效果应从三个层次解释。第一层是规则与状态的可执行性：候选有稳定身份，机制有独立开关，调度后仍经执行器和守卫。第二层是工程过程的可追溯性：记录可以将候选、计划、工具对象及原文连接起来，并区分历史重读、当前观测与控制器事实。第三层才是研究效果，即真实模型是否减少错误丢弃、在反证后更有效地检查，以及定位与成本是否改善。当前前两层已有材料，第三层尚待实验，不能因前两层通过就推导第三层成立。

相同入口 503 的案例说明需要检查依赖与日志，而不是证明某一调度必然最优。第三轮重置失败的案例说明控制器能保存失败并停止本批后续流程，而不是证明所有异常均可恢复。保留这些限制有助于明确系统的实际适用范围。

### 5.2 方法适用性与代价

有限保护适用于候选仍有可执行鉴别检查、早期缺乏支持但尚无可靠反证的情况。若候选解释本身错误，保护可能延长无效方向；若模型已经持续保留它，保护可能不额外改变行为。因而需要同时记录机会、实际改查及后续证据支持，不能只统计 protected 事件。

矛盾调度依赖可解析的必要预期和足够覆盖的现场记录。自由文本解释没有被有限条件完整表达时，系统只能判断该条件，不能宣称整段解释已被数学证明为假。反证出现却没有合法替代检查时，阻塞是当前能力边界；原模型本已选择相同检查时，也不能把该检查全部归功于机制。

四组共享结论门槛使错误结论的约束保持一致，但不能消除模型随机性、工具顺序和样本设计的影响。正式比较需在隐藏答案、独立状态和固定知识条件下完成。单台电脑的小型测试业务可用于本科演示和机制研究，不直接代表生产环境中的依赖规模、权限和故障复杂度。

### 5.3 参数与实验解释

保护期限 K 的默认值为 2，是当前实现配置，不是已通过效果实验选出的最优值。K=0 时不提供期限内保护；增大 K 可能增加候选核查机会，也可能增加无效检查。若未来比较不同 K，应在开发样本上确定范围并保留调参记录，最终保留样本不反复用于选择参数。当前不把参数扫描扩展为新增必达研究。

总步数、工具能力、超时及合法检查去重会共同影响机制是否有机会发挥作用。若步数不足以检查受保护候选，不能把保护事件出现解释为完成保护核验。完整耗时还应包含模型等待、失败重试与工具调用，不能将已有部分工具计时总和充当调查时延。费用缺 usage 时保持未知，不因本轮免费核验而回填为零。

## 第六章 总结与展望

本项目已将有限假设保护与可靠矛盾触发接入同一调查实现，保留候选状态、现场证据、实际检查与共享结论门槛。工程链路能够记录真实测试业务的观测，并在固定决策或历史输入下核对机制调度、报告输出、刷新读取与异常停止。PDF 知识和人工处理建议已纳入来源约束，不把手册描述或建议视为现场事实。

当前可以得出的结论是：研究方法已有可核查实现，相关工程边界已有分批记录；尚不能得出两项机制提升自主定位正确率、降低总体成本或具有生产泛化能力的结论。固定候选的成功改查不能证明自主模型曾丢弃正确解释，引用存在不能证明因果正确，未定位报告是否诚实仍需人工结合事实审核。

后续研究首先核对正式题目、学校要求和文献原文，完成用户亲手复现；真实模型继续遵守单独授权与费用核验约定。在具备条件后，以保留样本运行同一实现的四组实验，完整记录失败、usage 和费用，并根据实际结果重写摘要与研究结论。若没有额外收益，应讨论机制适用范围与检查代价，而非更换样本直至得到提升。

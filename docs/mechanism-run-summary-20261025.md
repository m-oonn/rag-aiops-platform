## 实现与核对口径

新增 `scripts/summarize_mechanism_runs.py`，读取原成功清单、各场 events/calls/mechanism_trace、知识前后审计及上轮只读重建的行为记录。核对组别、线程、真实配置、已完成步骤、工具调用顺序、知识条件及原 checkpoint/trace 的 hash。输出独立 `summary.json` 与可阅读的 `summary.md`，不覆盖旧文件。

同时扫描实际 mechanisms-* 目录：即使中断运行未进入成功清单，也保留一行并标明缺件，不能从分母静默消失。缺组、重复组、工具记录不一致、非法耗时、旧源变化或行为未通过都会阻止汇总一致性放行；已完成流程与缺行为审核分别记录。比较有缺口或未完成时，不计算对G00差值。

流程完成仅表示有非空 complete 报告且无 error 事件，不代表诊断正确或工具全部成功。报告类型、工具成功/失败、行为状态、阻塞和三类人工待审分列。当前不导入人工结论，不计算准确率；后续接入真实审核时必须核验审核包与源绑定。

工具耗时只加总有限、非负的 elapsed_ms，并记录覆盖次数；缺字段为未知，0可作为有效记录，布尔值、负数、NaN拒绝。工具计时可能重叠且缺准备阶段，不能等同完整诊断时间。原固定决策记录无本场模型费用账本，model_cost_cny 保留 null，不写成免费模型实验，更不改既有累计费用。

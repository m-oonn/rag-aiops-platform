## 4. 架构级修复详解（F 组三方案）

### 方案 A：MCP 客户端按 server 容错
- **根因**：第三方 `MultiServerMCPClient.get_tools()` 用 `asyncio.gather(return_exceptions=False)`，任一 server 失败抛 ExceptionGroup，已加载工具整体丢弃
- **修复**：`load_mcp_tools_safe` 逐个 server 独立 try，单点失败只跳过该 server
- **收益**：停 monitor 后仍有 6 工具（日志+知识库）可用

### 方案 B：证据充分性门控（诚实性）
- **根因**：`"工具不存在,跳过"` 被当中性观测，竞争归一强分摊概率，输出貌似确定的结论
- **修复**：`_evidence_sufficiency_problem` 检测日志证据缺失 → `_local_respond` 输出"结论(证据不足)"
- **收益**：信息不足时不伪装确定

### 方案 C：本地日志降级源（可用性）
- **根因**：日志是网络/OOM/混沌/依赖 4 类场景的唯一鉴别证据，但查询完全托付 MCP 服务
- **修复**：cls_server 每次 `search_log` 落盘 `runtime/log_cache/{topic}.json`（模拟真实系统"日志有本地磁盘副本"）；executor 在 `search_log` 不可达时降级读取，观测与在线等价
- **收益**：停 cls 命中率 5/8→**7/8**（2026-09-08 复验实测；网络场景原误判外部依赖 71%，经方案 D topic 对齐修复后判对 93%；场景 1 残差为 CPU 指标单源证据 + 日志全 INFO 无佐证，诚实输出 `uncertain` 不虚报）；降级来源可审计

### 报告双轨输出（人读 + 机读）
- 人读：`## 结论` / `## 结论(证据不足)` + ⚠️ 降级来源标注
- 机读：`<!-- diagnostic_meta: {evidence_sufficiency, note, conclusion_state, top_hypothesis, top_probability} -->`

## 6. 遗留边界（论文"局限"素材）

以下每条按「现象 → 根因 → 影响范围 → 缓解方向 → 论文写作建议」展开，供论文"局限性"章直接引用。

### 6.1 盲测配置局限

- **现象**：40 个盲测场景（5 根因 × 难度 0/1/2 × 多种子）全部由规则裁判判对，但均为"主治症状"配置——即每个假设的最强特征词按设计命中，未构造对抗性样本。
- **根因**：盲测生成器（`blind_fault_gen`）是基于剧本模板的参数化采样，特征词来自同一词表；未引入词表外的同义表达、方言化日志或 LLM 语义裁判单独退化场景。
- **影响范围**：鲁棒性结论的上界被高估——40/40 说明"在特征词表覆盖范围内"判定鲁棒，但不能外推"任意日志措辞"。
- **缓解方向**（后续）：①盲测生成器加入词表外扰动（同义词池、错别字、大小写混排）；②构造"症状重叠"对抗样本（两假设特征词并存，验证竞争归一）；③配合 LLM 语义线（配额恢复后）交叉验证。
- **论文建议**：把盲测结论限定表述为"在预设特征词表覆盖范围内检索鲁棒"，避免被质疑以偏概全；可将对抗性样本作为"未来工作"。

### 6.2 校准口径混合（B 组 ECE 近似）

- **现象**：ECE = 0.1645 由 47 点计算，但置信度来源有两种口径——部分取报告文本的百分比（四舍五入到 1%），部分取假设空间概率浮点值，两者混合计算。
- **根因**：`run_explainability` 在报告生成与内部 `hypothesis_space` 两处采集概率，未统一归一来源；低置信段（<0.65）仅 2 个样本，分箱统计噪声大。
- **影响范围**：ECE 是近似值，不能作为严格校准指标对外宣称；但"系统性低估、无过度自信"的方向性结论不受影响（47 点中 45 点实际正确率 ≥ 置信度）。
- **缓解方向**（后续）：①统一从 `hypothesis_space` 单一来源取概率；②扩充低置信段样本（设计"信息不足"场景批量采样）；③汇报 ECE 的同时给 EOE（Expected Overconfidence Error）以证明方向。
- **论文建议**：论文中把"0.1645"标为"近似 ECE"，并强调方向性结论（校准健康、无过度自信）而非绝对值；若答辩追问精度，坦承样本与口径局限并给出改进路径。

### 6.3 置信度基准仅覆盖规则线

- **现象**：校准与盲测结论全部基于确定性规则裁判（llm_stub + 规则证据判定）；真实 LLM 语义裁判线因 DashScope 免费配额耗尽未在本轮复测。
- **根因**：LLM 语义线在历史实验（303 决策文档）中已发现 Δ = -12% 的执行链路噪声（executor 逐步观测偏差、裁判降级），本轮环境无法稳定复现真实 LLM 路径。
- **影响范围**：E 组"降级等价性"（15/15 逐场景一致）证明规则线可替代语义线做确定性验证，但反过来"语义线上动态策略更优"尚无本轮数据支撑。
- **缓解方向**：配额恢复后用真实 LLM 复跑 E 组 + B 组，重点验证：①语义裁判下校准是否仍健康；②与规则线结论对照。
- **论文建议**：主证据用规则线确定性结果（可复现、无随机性），语义线作为"待完善验证"的补充实验，并交代 303 决策文档中语义线 Δ 为负的口径归因（执行链路噪声，非裁判本体）。

### 6.4 本地日志缓存时效与一致性

- **现象**：`runtime/log_cache/{topic}.json` 由最近一次成功的 `search_log` 写入；若日志服务停机时间超过缓存新鲜度窗口，降级读取到的可能是旧日志。
- **根因**：降级源是"镜像副本"而非"实时流"，没有 TTL/版本/时序回放机制——mock 场景无时间演化，但真实系统日志是持续追加的。
- **影响范围**：诊断结论可能基于过期观测；`source` 标记（`本地副本降级`）已让人/机可区分实时与副本，但未量化副本"陈旧度"。
- **缓解方向**：①缓存写入带时间戳与 TTL，降级读取时计算并上报陈旧时长；②缓存按服务轮转（多份快照），读取最新可用；③在报告中把陈旧时长并入 `diagnostic_meta` 的 `note`。
- **论文建议**：把该机制定位为"模拟真实系统日志落盘/采集冗余的高可用手段"，并明确其与生产"副本滞后"（如 Kafka 消费延迟）为同类 trade-off；陈旧时长上报可列为工程化后续。

### 6.5 首次冷启动无缓存

- **现象**：从未成功查询过的 topic 无本地缓存，cls 停服时 `_local_log_fallback` 返回 None，仍走方案 B"结论(证据不足)"诚实标注。
- **根因**：缓存是"有查询才有缓存"的被动写入；盲测动态主题（topic-blind）的缓存生命周期与 eval 场景文件绑定，独立运行诊断时可能尚未生成。
- **影响范围**：冷启动 + 故障叠加的极端场景只能给出"证据不足"结论（正确但低信息量）；这是设计内兜底，不影响命中率统计（F 组预先生成缓存）。
- **缓解方向**：①启动时预热常用主题缓存；②cls 服务恢复后主动补写；③方案 B 与方案 C 的自然互补已保证不会虚报。
- **论文建议**：将"冷启动回退诚实标注"表述为机制的优雅降级而非缺陷；可作 6.4 的对偶案例（一个解决时效、一个解决首启）。

### 6.6 F 组基线口径与"虚报"问题

- **现象**：修复前 F 组 5/8 的"命中"中，3 个是竞争归一强选先验的**虚报确定**（如 cls 停时 OOM 判"基础设施 31%"）；修复后 7/8 为真实证据驱动（停 cls 实测，2026-09-08），仅剩 1 个单源指标证据不足的诚实 uncertain。
- **根因**：修复前无证据充分性门控，top 概率 <0.5 也被输出为确定性结论；该缺陷同时存在于报告语义与评估口径（verify 只比对 Top1 字符串）。
- **影响范围**：任何"只看结论字符串"的评估都会把虚报算作正确，掩盖确认缺陷；这提醒实验必须区分"判对根因"与"有依据地判对"。
- **缓解方向**：①verify/实验脚本增加 `conclusion_state` 断言（conclusive 才算通过，degraded/insufficient 需人工复核）；②评估指标区分 Precision@Top1 与"标注置信的 Precision"。
- **论文建议**：这是"可解释性/诚实性"章节最强的论据——基线 LLM 黑盒报告无法区分"确定"与"瞎猜"，而本机制显式声明不确定性；可配合 `diagnostic_meta.conclusion_state` 做一个量化对比（T1 的 insufficient 标注率 vs T2 无此概念）。

### 6.7 场景覆盖规模与拓扑简化

- **现象**：全部端到端/盲测/鲁棒性验证跑在 `mock_scenario` 剧本上——单服务简化拓扑、脚本化故障注入（混沌注入也是剧本返回叠加，非真实流量扰动），未覆盖多服务调用链传播、真实时间序列演化与故障自愈。
- **根因**：论文侧验证目标是确定性复现（llm_stub + 固定种子），剧本化是刻意为之；真实数据采集/标注成本高，未纳入本轮范围。
- **影响范围**：级联依赖场景（`cascade_dependency`）只验证了"单服务故障在 mock 日志里的因果链优先"，未验证跨服务真实传播；任何"诊断真实分布式系统"的结论都属外推。
- **缓解方向**：①引入双服务/调用链剧本（A 服务故障 → B 服务 5xx，验证证据链回溯）；②真实故障注入工具（如 chaos-mesh 的 timeout/crash 注入）按需接入；③以真实生产日志切片回放（同 6.1 的"真实数据校准"扩展）。
- **论文建议**：把验证范围明确表述为"剧本化故障注入下的机制验证"，将真实调用链传播列为未来工作；鲁棒性主张限定在"机制在证据缺失/来源降级下的表现"，而非"生产环境定位准确率"。

### 6.8 阈值常量与关键词词表的"对测试集调优"风险

- **现象**：决策依赖 20+ 阈值常量（`_RESPOND_THRESHOLD=0.70`、`protection_rounds=2`、复活净支持门槛 2 等）与规则裁判关键词词表，这些值在历次实验（5 场景 → 8 场景 → 盲测 40 场景）中按测试结果逐步微调，未做系统性敏感性分析。
- **根因**：常量调优是"实验驱动"而非"独立验证集驱动"；词表来自剧本日志的真实措辞，天然与 mock 剧本同分布。
- **影响范围**：8/8、40/40 的高命中率存在"在自身剧本分布上过拟合"的质疑空间；敏感性未知意味着评审无法判断结果对超参的稳定性。
- **缓解方向**：①超参敏感性报告——对 2~3 个关键常量（respond 阈值、gap、复活门槛）做 ±20% 网格扫描，汇报命中率/步数变化带；②用 hold-out 剧本子集做"未调参评估"；③关键词词表做 leave-one-word-out 扰动。
- **论文建议**：主动公开调参史（决策文档/修复记录已是证据），并在论文中给出关键常量敏感性曲线，把"过拟合质疑"转化为"已验证的稳定性带"；表述为"阈值在 ±20% 内结论不变"更稳妥。

### 6.9 可解释性验证深度：结构性而非认知性

- **现象**：A 组"决策可审计性"验证的是**结构性存在**——T1 有信念轨迹/Top3 置信集/证据映射/决策记录，T2 没有（4/4 非对称）；但未验证"人类工程师读完 T1 报告后决策质量是否真的提升"。
- **根因**：认知验证需要受控用户研究（被试、任务、耗时/正确率/信任度量表），超出本轮自动化实验范围。
- **影响范围**："结构可审计"≠"人可理解"；若答辩追问"可解释性对使用者的实际收益"，现有数据只能回答"机制层面提供了可解释材料"，不能回答"人是否用得上"。
- **缓解方向**：四维 A 组基础上补小型用户研究——同一批故障报告（T1 结构化 vs T2 黑盒）给工程师读，统计：①定位正确率；②平均决策耗时；③自评信任度；④是否依据"证据→假设"映射溯源。
- **论文建议**：行文区分"机制可解释性（本轮已证）"与"认知可解释性（未来工作）"；避免把"我们提供了解释材料"写成"我们的解释更有效"。

### 6.10 裁判之外的 LLM 组件未进验证矩阵

- **现象**：论文侧实验用 llm_stub 确定性桩替代真实 LLM；真实 LLM 仅在裁判环节（语义线）被讨论，但 **planner（计划生成）与摘要环节**仍走桩——真实 LLM 的格式漂移、幻觉、指令未遵从未被纳入验证；RAG 知识库线（`rag_server`/`local_retrieval`）在本轮实验也未覆盖。
- **根因**：qlm_stub 是端到端可复现性的前提（固定种子）；真实 LLM 可用性（配额/网络）不稳定，无法进入确定性验收闭环。
- **影响范围**：结论只能支持"给定正确计划与忠实工具结果时，裁判与决策机制有效"；"计划生成质量对根因定位的影响"无数据；知识库证据线对诊断的增量贡献未被量化。
- **缓解方向**：①配额恢复后做一次真实 LLM 全链路冒烟（planner+摘要真实，裁判与决策层不变），对比桩 vs 真实的三组指标；②知识库线补 1~2 个"检索命中/未命中"对照场景，量化 RAG 增量。
- **论文建议**：明确限定贡献范围为"（stub 稳定计划下的）证据裁判与动态决策机制"；把 planner/摘要/知识库的验证列为后续章节或未来工作，避免评审误读为全链路真实 LLM 实验。

---

## 7. 结论

系统在 **8 个真实场景（含复杂/混沌）+ 40 个盲测 + 四组扰动实验**下全面验证：

- **创新点有效性**：可解释性（4/4 结构非对称 + ECE 0.1645 健康校准 + 100% 稳定性）与鲁棒性（输入/降级/故障/复杂度四维）均有确定性实证
- **架构加固**：MCP 单点依赖与日志证据单点依赖两大脆弱点已从根上消除
- **诚实性设计**：信息缺失时显式声明"证据不足"，降级来源可审计、可机器消费

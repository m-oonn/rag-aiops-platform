# 自主实验记录的下游消费与比较门槛

2026-10-25。新增记录已接入实际控制器与只读自主汇总，不只落盘。未调用真实模型、制造故障或启动停止服务。

## 改动与边界

- scripts/evaluation_record.py 的 audit_evaluation 重算配置指纹，核对必需源码、副本文件集合/hash，控制器调用时还对照当前工作树。检查运行/请求/工具计时、模型输入hash及元数据、served_model、完整usage、继承前缀、累计/本场费用、报告与完成事件、机制轨迹及知识条件。路径不得逃出对应目录。这里只核验记录完整性，不证明因果正确或防御所有联合篡改。
- evaluate_windows_probe.py 为实际发送的脱敏参数文件补 input_sha256，不回填旧请求。
- verify_windows_local_faults.py 在新场次放行前调用同一核验，写 record-integrity.json；失败停止后续场次并保留材料。返回记录分列本场费用与原累计账本。
- 新 scripts/summarize_evaluations.py 只读消费自主运行产物及控制器model-attempt记录，保留失败、缺件和旧格式。四组每场景各一条，源码/依赖、固定配置、实际模型采样参数、知识条件一致且记录完整，才计算对G00的本场请求/预留与run_model时间差。不同场景不能仅凭provided_symptom标签配组，要求控制器场景映射；模型动态函数调用格式不充当固定采样参数。
- 旧 summarize_mechanism_runs.py 继续只读汇总固定决策历史，不将新自主数据与旧固定决策拼接。人工意见保持pending，human_reviewed=0，diagnostic_accuracy=null；工程差值不表示独立试验、因果开销或创新有效。

严格比较会拦截不同随机端口、路径和允许对象，当前没有暗中归一化。下一步需免费核对同一现场四组固定条件的控制器编排；本轮没有解决或验收这项能力。运行时间仅指已标注的run_model阶段，控制器时间仅到子进程wait，均不是包含注入/审核/恢复的整场实验时间。

## 用法与下一入口

只读汇总：在项目根目录执行 .venv/Scripts/python.exe -m scripts.summarize_evaluations --source 原运行根目录 --output 新独立输出目录。退出失败可以是缺件/条件不齐的正确拒绝，不能据此删掉记录。来源目录须为可信本机实验材料，原产物保留。

下一步免费核对同一现场四组编排：各组独立状态，固定允许对象/知识/模型与执行预算，答案隔离，失败和恢复留痕；先用替代决策验证编排，不启动真实模型或新故障。需要掌握：记录完整不等于诊断正确，相同组名不等于相同条件。系统完成新门槛接线与离线验证，尚无用户独立复现的新记录。

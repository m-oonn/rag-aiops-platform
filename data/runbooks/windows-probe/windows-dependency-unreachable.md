# Windows 应用下游依赖不可达排查

手册只提供调查方向，不能代替现场探测结果。

1. 先确认应用入口的 TCP/HTTP 现象，再对配置中已登记的依赖执行 DNS、TCP 和固定 GET 健康检查。
2. 区分 DNS 失败、TCP 连接失败、HTTP 超时、HTTP 5xx 和应用自身返回错误；这些现象的因果含义不同。
3. 查询应用白名单日志，寻找与同一时间窗对应的连接失败、超时或上游状态码，并核对 `target_id` 和采集时间。
4. 依赖不可达只能在应用错误与依赖探测时间一致、且关键替代解释已检查时作为根因候选；否则报告未定位。

依赖地址必须来自本机配置。Probe 不允许探测任意新地址，也不发送 POST、认证头或修改请求。

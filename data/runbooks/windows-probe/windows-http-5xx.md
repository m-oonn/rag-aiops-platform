# Windows 应用 HTTP 5xx 排查

这是只读调查顺序，不是具体业务的根因结论。

1. 记录入口 HTTP 状态、响应时间和采集时间，同时确认入口 TCP 是否正常。
2. 若 TCP 正常但返回 5xx，查询配置中的应用日志和 Event Log，区分应用内部错误、上游失败和健康检查实现错误。
3. 对配置中的依赖做有限健康检查，并将依赖结果与应用日志中的时间和错误类型对齐。
4. 不能仅凭一次 5xx 或知识库经验下确定性结论；至少需要一条现场原始日志或依赖证据直接支持主假设，并检查关键替代解释。

Probe 只读取现场数据。修改配置、发布回滚、重启服务和重放业务请求不在自动诊断范围内。
